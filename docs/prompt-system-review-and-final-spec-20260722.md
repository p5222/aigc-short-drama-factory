# 漫角内置提示词评估与最终方案

更新时间：2026-07-22

## 一、评估范围

本次对照了项目当前实现与以下外部提示词：

- `小说转剧本.txt`
- `漫剧人物场景提取.txt`
- `人物三视图.txt`
- `场景四视图.txt`
- `15s即梦剧本分镜指令.txt`
- `10s豆包剧本分镜指令.txt`
- `漫剧风格分类清单（分区版）.xlsx`

项目当前对应实现主要位于：

- `apps/api/src/agents/generator.ts`
- `apps/api/src/agents/toonflowAdapter.ts`
- `apps/api/src/agents/storyboardProduction.ts`
- `apps/api/src/db/storyboardActions.ts`
- `apps/api/src/db/repository.ts`

## 二、总体结论

外部提示词适合提供“生产经验规则”，项目当前提示词适合提供“结构化输出和数据连通”。最终不能直接复制外部提示词，而应采用：

```text
外部提示词的制作规则
+ 项目现有的 JSON 数据结构
+ 角色/场景/镜头资产引用机制
+ 分阶段质量检查
= 漫角最终内置提示词系统
```

最重要的合并原则：

1. 原文是剧情事实唯一来源，提示词只能拆解和重排，不能擅自新增角色、场景、动作和心理活动。
2. 角色外貌由角色资产锁定，分镜只描述动作、情绪、站位和镜头语言。
3. 场景由场景卡锁定，分镜只描述当前镜头使用的空间区域、光线和动作关系。
4. 静态图片提示词只负责首帧，视频提示词只负责首帧之后的连续动作。
5. 平台差异只放在模型适配层，不应该污染剧本和分镜主数据。

## 三、外部提示词评估

### 1. 小说转剧本

外部提示词的优点：

- 强调台词和原文内容不能被随意改写。
- 能把小说内容拆成可拍摄的动作、对白和场景。
- 有明显的短剧节奏意识，强调冲突、悬念和结尾钩子。
- 输出中已经隐含角色和场景提取需求。

需要保留的规则：

- 原文事实约束。
- 角色关系和冲突提取。
- 可视化动作优先。
- 每集结尾保留推进下一集的钩子。

不建议直接采用的部分：

- `set_all_text`、加粗字段等编辑器操作指令。这些不是模型内容规则，应由前端或编辑器处理。
- 过长的输出示例。示例过长会污染模型，导致角色、场景和动作串到新故事中。
- 把 10 秒或 15 秒分镜格式混进小说改编阶段。

项目当前已经有剧本 JSON 输出和角色卡字段，建议补充独立的故事事实层：

```json
{
  "synopsis": "...",
  "episodes": [],
  "characters": [],
  "scenes": [],
  "props": [],
  "storyFacts": [],
  "script": "..."
}
```

### 2. 人物与场景提取

外部提示词的优点：

- 要求完整提取每一个人物和场景。
- 要求输出别名、描述和出现次数。
- 对角色服装、鞋子、年龄、时代、风格有较强约束。
- 场景描述已经接近可直接用于生图的结构。

需要保留的规则：

- 每个实体只建立一次主记录。
- 同义名、别名需要归并。
- 出现次数和首次出现位置要保留。
- 角色服装和场景固定元素要进入资产锚点。

需要改造的部分：

- “加粗文本”“替换全文”属于外部工具指令，不进入模型提示词。
- 人物和场景不能只输出自然语言段落，应输出结构化 JSON。
- 场景需要增加固定机位、空间锚点、光线方向、可复用道具和时间天气。

### 3. 人物三视图

外部提示词的优点：

- 明确指定正面、侧面、背面。
- 强调三视图比例、脸型、五官、服装和配饰一致。
- 纯色背景有利于模型识别角色。
- 对单套服装、单套鞋子有明确限制。

项目当前较好的部分：

- 已支持参考图身份提取。
- 已支持角色身份板资产回写。
- 已支持后续分镜引用角色参考资产。

最终建议：

- 生产主资产采用“左侧头像特写 + 正面/3/4/背面全身”的标准身份板。
- 不把大量姿态研究、复杂文字标签放入主身份板。
- 表情研究、姿态研究、服装细节放为可选扩展图，不作为分镜主参考图。
- 图像提示词中禁止生成文字、标签、编号和水印，避免文字渲染污染。

### 4. 场景四视图

外部提示词的优点：

- 四个视角共享同一场景。
- 明确要求物体比例、材质、光照完全一致。
- 强调场景内物体静止，只改变摄像机位置。
- 适合建立连续镜头的空间参考资产。

最终建议保留四视图逻辑：

1. 场景整体全景
2. 正向中景：从入口向内
3. 反向中景：从深处向外
4. 核心区域近景

需要补充：

- 场景名称和唯一 ID。
- 入口、出口、主光源、固定道具。
- 前景、中景、后景锚点。
- 可出现角色的站位区域。
- 昼夜、天气和镜头可变范围。

### 5. 15 秒即梦分镜提示词

外部提示词的优点：

- 时间轴表达清楚。
- 强调动作连续性和前后镜头衔接。
- 有首帧、动作段、尾帧的意识。
- 强调自动配音、中文对白、禁止字幕。
- 对每个时间段的景别、运镜、动作、音效都有要求。

主要问题：

- 示例里存在角色和场景错配，容易让模型复制示例中的“班长、递笔”等无关内容。
- 将 15 秒视频切成多个独立动作时，可能导致镜头过度拥挤。
- 具体平台指令和通用分镜规则混在一起。

### 6. 10 秒豆包分镜提示词

外部提示词的优点：

- 更强调单段动作的简洁性。
- 适合短视频模型快速生成。
- 对前一镜尾帧到后一镜起始状态的衔接要求明确。

主要问题：

- 示例重复污染严重。
- 将平台输出格式和剧情生成规则写在同一层。
- 10 秒与 15 秒版本的字段标准不统一。

最终做法：

```text
统一内部镜头数据结构
        ↓
根据目标平台生成 10 秒或 15 秒适配提示词
```

不再维护两套完全独立的剧情分镜逻辑。

## 四、最终内置提示词结构

### A. 小说转剧本提示词

系统层核心规则：

```text
你是短剧策划和编剧。你只能使用用户提供的原文事实。
不得新增原文没有出现的角色、地点、事件、动作、关系或心理结论。
你的任务是把原文整理成可生产的短剧剧本，并提取角色、场景、道具和故事事实。
输出合法 JSON，不输出 Markdown，不输出解释。
```

用户层变量：

```text
作品名称：{{title}}
输入类型：{{sourceType}}
目标集数：{{targetEpisodes}}
题材：{{genre}}
画幅：{{videoRatio}}
用户选择的视觉风格：{{styleProfile}}
原文：{{content}}
```

必须输出：

```text
synopsis
episodes
characters
scenes
props
storyFacts
script
```

### B. 人物与场景提取提示词

核心规则：

```text
只从已确认剧本中提取实体，不创造新实体。
同一人物的姓名、别名、称呼必须归并到同一个 characterId。
同一场景的不同叫法必须归并到同一个 sceneId。
服装、发型、配饰、固定道具、主光源和空间锚点必须结构化保存。
```

人物输出建议：

```json
{
  "id": "character_001",
  "name": "",
  "aliases": [],
  "identity": "",
  "ageRange": "",
  "appearance": "",
  "costume": "",
  "signatureProps": [],
  "personality": "",
  "firstAppearance": "",
  "appearanceCount": 0,
  "lockedAnchors": []
}
```

场景输出建议：

```json
{
  "id": "scene_001",
  "name": "",
  "aliases": [],
  "description": "",
  "time": "",
  "weather": "",
  "lighting": "",
  "foregroundAnchors": [],
  "midgroundAnchors": [],
  "backgroundAnchors": [],
  "fixedProps": [],
  "characterBlockingZones": [],
  "appearanceCount": 0
}
```

### C. 人物身份板 / 三视图提示词

核心规则：

```text
只生成一个角色，不新增人物。
使用角色身份卡和参考图锁定同一张脸、发型、服装、配饰、年龄感和身体比例。
生成单张 16:9 生产参考图：左侧头部特写，右侧依次为正面、四分之三侧面、背面全身。
四个视图必须是同一角色、同一套服装、同一比例、同一光照。
纯净浅色背景，不生成文字、标签、编号、Logo、水印、分格边框和额外人物。
```

### D. 场景四视图提示词

核心规则：

```text
只生成同一个场景，不生成角色。
生成一张 16:9 四视图场景参考图：整体全景、入口向内、深处向外、核心区域近景。
四个视角共享同一空间、同一物体比例、同一材质、同一光照和同一固定道具。
只改变摄像机位置，不改变场景内物体。
禁止人物、文字、字幕、Logo、水印、拼贴、分镜编号。
```

### E. 剧本分镜提示词

分镜模型只负责产生结构化镜头，不直接生成平台专属长提示词。

每条镜头必须包含：

```text
episodeNo
sceneNo
shotNo
duration
shotSize
cameraAngle
cameraMovement
characters
scene
pictureDesc
action
orientation
spatialRelation
dialogue
voiceOver
environmentSound
soundEffect
emotion
imagePrompt
videoPrompt
```

分镜规则：

1. 当前镜头只能承载一个主要动作或一个明确情绪变化。
2. 台词只能来自原文，不能改写或扩写。
3. 必须引用真实的 characterId、sceneId 和 assetId。
4. 多人同框写清 screen-left、center、screen-right 及前中后景。
5. 保持 180 度轴线和前后镜头空间连续。
6. `imagePrompt` 只描述首帧静态画面。
7. `videoPrompt` 只描述从首帧开始的动作、声音、尾帧和衔接。
8. 不生成字幕、标题、解释文字、水印和 Logo。

## 五、风格分类表接入方式

风格表目前有 4 个分区：

1. 二次元类（漫剧）
2. 3D 类（漫剧）
3. 写实类（真人剧）
4. 其他风格类

每个风格包含：

```text
styleName
styleDescription
styleCategory
```

用户选择风格后，不应只把风格名称传给模型，而应注入完整风格档案：

```text
用户选择风格：{{styleName}}
风格分区：{{styleCategory}}
风格定义：{{styleDescription}}
```

推荐注入位置：

- 小说转剧本：只注入风格对故事视觉方向的影响，不让风格改变剧情事实。
- 人物提取：注入角色外观和服装的风格化边界。
- 人物身份板：注入渲染材质、线条、比例和光照方式。
- 场景四视图：注入材质、环境光和空间表现方式。
- 分镜首帧：注入构图、色彩、镜头质感和画面调色。
- 视频提示词：注入运动质感、光影连续性和渲染稳定性。

不要把风格描述直接重复拼接 5 次。建议先转成统一的 `styleProfile`：

```json
{
  "name": "3D 卡通渲染（三渲二）",
  "category": "3D 类（漫剧）",
  "visualLanguage": "3D 建模、卡通渲染、色彩鲜艳",
  "characterRules": "角色比例清晰，轮廓稳定，材质干净",
  "sceneRules": "空间层次明确，色彩统一，光照柔和",
  "cameraRules": "优先使用清晰中景和稳定推拉镜头",
  "negativeRules": ["写实皮肤纹理", "复杂文字", "水印"]
}
```

## 六、最终建议的提示词版本体系

建议建立以下 5 个主模板：

```text
novel_to_script_v1
entity_extraction_v1
character_identity_board_v1
scene_environment_sheet_v1
storyboard_core_v1
```

平台适配作为独立模板：

```text
storyboard_video_seedance_15s_v1
storyboard_video_doubao_10s_v1
```

这样后续可以分别评测：

- 同一模型，不同主提示词
- 同一提示词，不同模型
- 同一故事，不同风格档案
- 10 秒和 15 秒视频适配效果

## 七、后续实现顺序

1. 先把外部提示词的规则整理进统一模板，不立即改变现有业务接口。
2. 增加 `styleProfile` 解析和风格选择注入。
3. 将人物、场景从剧本输出中独立成实体提取阶段。
4. 统一角色身份板和场景四视图格式。
5. 将 10 秒、15 秒提示词改成同一份分镜数据的适配器。
6. 为每个阶段增加输出校验和失败原因。
7. 再接入 `PromptVersion` 和 `ExperimentRun` 做模型与提示词对比。

## 八、最终判断

外部提示词最值得吸收的是：

- 原文约束
- 角色和场景完整提取
- 三视图 / 四视图一致性
- 时间轴动作拆解
- 前后镜头衔接
- 平台生成限制

不建议直接吸收的是：

- 长篇示例文本
- `set_all_text` 等编辑器命令
- 直接控制第三方平台的指令
- 强制模型生成大量中文图片文字
- 将 10 秒和 15 秒逻辑写成两套完全独立流程

本方案可以作为下一步“内置提示词重构”的评审基线。你后续继续提供其他提示词时，直接按这 5 个主模板归类即可。
