# 创作质量与对话工作流

本轮把“创作要求 → 生成 → 定向修订 → 作者确认 → 媒体制作 → 成片检查”接入实际生产路径。它提升可检查性与修改效率，不保证模型一次写出可直接商业交付的故事。

## 各阶段的输入与检查

| 阶段 | 输入重点 | 产物与检查 |
| --- | --- | --- |
| 首作短片 | 受众、目标、阻碍、结尾、制作边界、禁用处理 | 可编辑剧本、目标/选择/回报、逐句节拍；检查来源、漏句、顺序、时长 |
| 标题与题材策划 | 原创意图、受众体验、篇幅 | 区分事实、推断与建议；不能把模型知识当成实时调研 |
| 大纲与章节 | 因果、人物选择、伏笔回收、前章后果 | 状态交接只记录已经发生的事，保留时间与知情范围 |
| 已有素材改编 | 原文与改写尺度 | 已有剧本正文直接保留；小说与分集改编不得补造关键事实 |
| 人物/场景/道具 | 已确认身份、布局、光向、材质 | 各自独立模板；角色身份参考、环境参考与单件道具分开 |
| 分镜与首帧 | 台词原句、站位、轴线、单镜目的 | 不以示例分镜替代真实生成失败；首帧只表达静态起点 |
| 图生视频 | 作者运动要求、镜头实际秒数、首尾状态 | 一个主动作与一种运镜，保留可剪辑停点 |
| 配音与字幕 | 分角色逐行对白、单独旁白 | 同一逐句清单供报价、音色、字幕与拼接使用；超长真实音频拒绝截断 |

## 作者如何对话

创作请求说明：“谁想完成什么，什么挡住他，结尾如何改变，哪些事实必须保留，制作有什么限制。”

修订请求说明：“哪里有问题，希望怎样变化，哪些内容必须保留。”例如：

> 第2场主角读完字条就改变决定，但观众不知道字条内容。只补出足以支持选择的可见线索，保留角色关系和结局，其他场次仅做必要衔接。

界面提供五个可选创作问题、四个可编辑修订方向，以及各阶段的创作方法。点击建议只补充输入；报价和提交仍是明确的后续操作。修改反馈后原报价失效。手改正文后，旧节拍依据标记为原版本依据。

## 运行约束

- 生成和自动修订共享已批准的调用与费用上限，最多两次；供应商结果未知时停止。
- 修订使用执行计划保存的提示词版本及原始系统文本，管理员随后发布新版本不会改变进行中的计划。
- 所有生产提示词采用可追溯版本；媒体任务保存实际使用的模板快照。仅文案更新且契约完全一致时保留已有自定义版本兼容性。
- 原创朗读估时不超过目标的三分之二，给动作与停顿留时；忠实素材和必须保留台词不受该原创预算自动删改。句数是写作建议，不是艺术质量评分。
- 同镜对白顺序在前、旁白在后；需要穿插旁白时拆镜。静音镜头保留时长，画面描述不自动变成字幕。
- DeepSeek V4 结构化 JSON 请求显式关闭默认 thinking，避免共享输出额度耗尽；输出达到 token 上限时清晰报错。

## 已知质量边界

18次真实 DeepSeek 调用暴露了格式之外的问题。最后一轮3个题材共5次调用，1稿通过当时自动检查，但3稿均未达到本次编辑评审的直接交付标准：正常打烊与放弃经营的动机区别、喜剧对白密度、监控日期证据及状态连续性仍需要作者判断。未继续无限调用来追求一个通过结果。

本轮保留失败稿并增加回归检查。规则通过、数据库回归、供应商 usage、配置费用、作者认可和真实账单分别记录。真实连续视频、音色质量、现金支付和受众反馈需要独立验收。本地完整样本和实用指南位于 `outputs/creative-quality-20261101/`。

## 方法依据

- [OpenAI 评测最佳实践](https://platform.openai.com/docs/guides/evaluation-best-practices)：实际任务评测、失败样本留存、用人的判断校准。
- [Runway Gen-4 提示指南](https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide)：简洁运动描述与逐项迭代；不代表其他供应商效果已验证。
- [BBC Maestro 剧本开场](https://www.bbcmaestro.com/blog/writing-an-opening-scene-for-screenplay)：具体场景、人物与后续故事关系。
- [DeepSeek thinking mode](https://api-docs.deepseek.com/guides/thinking_mode)：结构化创作请求的思考模式配置依据。
