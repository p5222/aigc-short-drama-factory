# 视频剪辑与成片交付技术说明

## 数据与接口

- 新增 `DeliveryEdit`：按项目和集保存有序片段，包含素材资产 ID、入出点、服务端记录的素材地址和 revision。原分镜与生成资产不变。
- `PUT /projects/:id/delivery-edit` 接收 `episodeNo`、`expectedRevision` 与 `clips`。请求中的片段仅包含 `shotId`、`sourceAssetId`、`inPoint`、`outPoint`。拒绝客户端素材 URL。
- 仅项目所属用户可修改；成功、可播放、当前项目与对应镜头的视频才能入选。历史资产 ID 按已有 UUID 格式筛选。
- 保存使用项目生命周期锁与行锁，校验预期版本。并发修改返回 409，前台保留草稿。
- 报价与导出支持 `deliveryEdit: { episodeNo, revision }`。服务器重建保存版本，复核视频 URL，随后固化导出快照；旧导出仍可读取并显示历史状态。

## 前台状态

各集有独立草稿、30 步撤销和手动保存。刷新从数据库恢复已保存剪辑；未保存修改仍是页面内草稿，离开页面存在丢失风险，因此提供导航确认和 JSON 下载。JSON 当前仅作为备份，没有实现导入恢复入口。

冲突提示不会清空输入。载入云端前确认是否放弃本集修改。保存响应成功但刷新失败时保留返回版本，禁用重复保存并提示核对。

原生播放器与自定义进度条都限制在当前保留区间。选用视频被重新生成替换后，暂停该素材预览与导出，要求显式确认新素材并保存。手机侧栏采用已有抽屉与焦点恢复逻辑。

## 导出与音频

FFmpeg 对选定视频按 `-ss` 和 `-t` 实际裁剪，不使用循环补齐。真实源视频过短时拒绝，避免重复帧冒充正常成片。时长保留小数，SRT 使用毫秒时间戳。

合成仍使用原有 TTS 配音策略，未实现源音频与 BGM 混音。裁剪后根据缩短的镜头时长适配配音和字幕，不提供字级音画同步。未新增编辑扣费项，配音费用与可复用输入由现有服务端报价判断；导出确认仍传积分上限。

## 数据库与发布

新增模型需运行项目已有的 Prisma generate 和受保护部署流程中的 db push。隔离数据库已验证新增表与并发行为，生产尚未应用。

回滚应用可恢复旧界面；新表应先保留，避免删除用户剪辑记录。旧应用不会读取这些记录。不要直接删除新增表或降低 revision。发布需要核对 GitHub main、服务器 main 与已部署 revision，再验证 readiness 和公开 UI。无法同步 GitHub 时不要绕过 revision 保护直接部署。
