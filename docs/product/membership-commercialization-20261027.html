采用「普通创作者 + 按量积分 + 两档月度会员」的组合。用户按创作频率选择权益，运营按真实订单识别付费与会员状态，价格由成本与毛利测算约束。

01 / 产品契约

先完成个人创作者的收费闭环

按量创作

普通用户拥有现有可用功能，通过充值或已有积分创作。会员是周期权益与积分组合，首批不新增功能封锁。

手动月付

看套餐 → 确认权益 → 核对订单 → 扫码付款 → 自动到账 → 查看本期与续费安排。

真实核对

会员以已支付订单对应的权益期为准。后台积分入账、商业会员身份、账号权限各自独立。

主要触发：用户进入积分充值页查看会员，或者现有会员临近到期主动续费。完成条件：支付已确认、积分仅入账一次、权益期限可见、订单可恢复；管理员可按会员状态准确查找账号。

第一批产品判断：复用现有积分充值页承载会员中心。支付未开放时仍展示真实套餐与已购权益，购买按钮说明暂停状态。保留既有卡密充值入口；普通积分兑换码不等同会员开通。

事实来源：现有会员授予、支付恢复、任务计费、启动配置保护代码。本文没有引用外部竞品价格或未经验证的用户数据。

03 / 会员产品

保留两档会员，先把权益说准确

普通创作者服务低频和探索需求；创作者会员面向连续个人创作；专业会员面向更高用量的个人创作者。这是产品定位判断，尚无用户访谈或转化数据支持。团队工作空间与企业版待后续需求验证。

产品积分与购买周期权益金额事实边界
普通创作者没有会员费。使用现有余额，积分充值按实际配置购买。标准队列；生成按实际报价。现有功能不新增会员门槛。首次体验额度、活动赠送不在本轮新增。
创作者会员本次支付即获得该档配置积分，永久有效。一个自然月；符合规则的任务结算减免；平台队列优先。仓库初始值：¥39.90 / 4,000 积分 / 10% / 等级 1。不是已核验的线上售价。
专业会员本次支付即获得该档配置积分，永久有效。一个自然月；较高的配置减免和队列等级。仓库初始值：¥129.90 / 14,000 积分 / 20% / 等级 2。不是已核验的线上售价。

前台以运营后台的当前配置展示价格、积分、减免比例和队列等级；已付订单保留购买时的权益。避免使用“每月自动发放”“所有模型九折”“无限生成”“保证更快完成”等不符合现有能力的承诺。

套餐编辑规则

运营可沿用既有套餐编辑和启停功能。调整仅影响之后的购买；旧订单金额、积分和权益期不改写。停售后原权益仍有效，同档续费按钮停用。默认启动流程保留运营改价和停用状态，首批只修改新建套餐的描述文本。

04 / 定价方案

用实际现金收入检验 40% 毛利目标

保留项目既有的成本计价与 40% 毛利目标。目标毛利下，服务收入应至少覆盖「可归属成本 ÷ 0.6」。支付手续费、算力、存储、失败重试与赠分带来的真实成本必须纳入核算；下方演示不代替供应商账单和实际现金验收。

任务层

以官方成本计价的任务按已配置规则报价。启用毛利保护时，会员减免可能被限制；会员不必然比非会员扣分更少。实际积分以生成前报价为准。

生成冻结、失败退款、实测用量差额及资金批次折算沿用积分系统，不在本轮重写。

会员包层

一笔会员收入附带永久积分负债。续费积分立即发放，不能把尚未消耗的积分当作无成本收入。需测算全部积分使用、常用模型组合、失败重试和提前续费场景。

低价充值、赠分与会员积分的现金单价不同；仅对标称积分做 40% 加价，不能证明真实现金毛利达标。

05 / 完整用户流程

购买之前明确承诺，支付之后能够恢复

看清权益当前身份、档位、积分数量、价格和暂停状态
确认购买手动月付、续费起点、本次权益和最终金额
核对付款订单与二维码、刷新状态、未知结果恢复
到账与续费积分余额、本期期限、已购到期及未来权益
FR-01 会员中心

登录用户从现有积分充值页进入。加载前显示读取状态；失败显示重试，不把失败当作普通用户。支付暂停也展示真实在售配置和现有权益。套餐均停用时说明暂无套餐，保留原订单权益展示。

FR-02 套餐比较

每档显示名称、每自然月价格、本次积分、永久有效、减免适用边界、队列等级与手动续费。展示当前档位；有效期内或有待确认异档订单时仅能选择同档。选择卡片不产生订单。

FR-03 购买确认

点击购买打开确认窗口；取消不创建订单。确认内容包括本次价格、即时积分、自然月、续费起点、权益比例、无自动扣款和付款前核对金额。确认后创建或恢复订单，成功进入现有收银区；请求失败保留确认和错误，支持核对重试。

FR-04 收银与恢复

扫码前显示最终订单金额、状态与截止时间。同一请求重试复用订单；待支付同套餐订单优先恢复。支付确认仅由服务端判断，浏览器不自行宣布到账。状态未知时提示继续核对，不引导重复付款。

FR-05 支付成功

确认后积分仅入账一次，刷新余额与会员。首购立即开始权益期；同档续费从已购末尾顺延，积分仍立即发放。长期任务按开始时的权益与计价规则结算。

FR-06 到期与续费

本期权益截止与已购到期分别显示。未来续费列出生效时间和对应权益，避免新权益提前作用。本轮增加到期状态和手动续费入口；主动提醒和自动续费尚未实现。

06 / 权益契约与异常

本期权益和未来权益分别生效

情况确定规则用户反馈与恢复
首次购买服务端确认支付后开始一个自然月，积分立即发放。显示已到账和本期起止日期，不承诺后续自动发放。
同档连续续费从已购到期顺延。每次支付即发本次积分。未来权益保留购买时的配置。显示本期截止、已购到期、待生效期与未来减免；不重复累加当前权益。
自然月边界按 UTC 日历月增加，月末不足同一天取月末。开始时刻保留。不是固定 30 天。页面日期按用户设备时区显示，月末规则写入说明。
有效期内跨档当前不支持；待确认异档订单同样阻止冲突购买。按钮说明仅能同档续费。升级差额、剩余积分和生效时点为 [TBD]。
二维码过期 / 迟到回调二维码失效不代表未付款。未解决订单继续保留档位保护，先核对或关闭供应商订单。刷新原订单查看结果；不能直接换档后重复支付。
套餐配置变化已创建订单和已付权益保留快照，新订单按新配置。付款前看最终订单金额。旧权益与新续费权益分别显示。
停售 / 支付暂停不能新购，原已付权益仍按期限展示。明确暂停原因的公开可用状态，不隐藏历史订单。
到期无当前权益时使用普通计价；账户积分不因到期清零。展示到期状态、原期截止，允许开放档位重新购买。
账号停用不自动冻结会员时间、不自动退款、不删除资金记录。运营联系支持处理争议。停用延期与补偿规则待决策。
退款 / 争议退款记录不能作为当前有效权益来源。本轮不新增一键现金退款。通过既有工单核对。已用积分、手续费、会员期回滚和已续费期调整须先定义并开发完整规则。

当前权益期为开始时间包含、结束时间不包含。任务排队优先与供应商处理速度是不同阶段，不承诺固定响应 SLA。对于未来续费，页面只展开最近 12 期，同时显示总期数和最终已购到期，避免无限增长。

07 / 运营工作台

能找到会员，也能辨认收入证据

FR-07 用户列表

增加商业身份列，显示有效、待生效、已到期或普通创作者，以及在线已付订单数量。会员状态筛选支持组合搜索、注册日期、角色、账号状态和分页。

FR-08 用户详情

只读显示当前档位、本期截止、已购到期和在线已付订单金额。明确不含卡密、赠送和人工调整；这个金额是已付订单汇总，不等同财务净收入或利润。

FR-09 运营视角

快捷入口提供有效会员、到期会员和在线付费用户。保持用户状态、密码、积分调整与草稿保护现有流程；首批不增加可手工篡改会员状态的开关。

FR-10 套餐治理

沿用现有套餐配置、启停与操作记录。新改价仅影响新订单；启动默认不覆盖运营配置。进一步增加收益测算、配置历史和档位变更预览安排后续。

客服闭环

订单未知、重复扣分疑问、到期与新权益疑问应带平台订单号或任务号进入既有支持工单。客服先查原记录，确认是否真实支付、是否已到账、是否是未来权益，再确定处理。禁止以“赠积分”代替对原付费状态的核对。

08 / 生命周期与运营

先建立口径，再做转化和召回

阶段运营方案统计口径状态
注册清楚说明首次创作、积分与会员选择；保留低摩擦登录恢复。指定期间新注册的有效账号数。账号功能已有；漏斗聚合待做。

续费本期与已购到期可见，主动同档续费；提醒须用户同意并独立配置。在固定观察窗口到期且可续费的会员中，窗口内有同档确认续费的占比。窗口 [TBD]。首批完成查看与操作；提醒待做。
流失召回按曾付费、成功作品与距上次创作时间排序，客服帮助恢复作品。长期未创作定义与触达频率 [TBD]；区分已续费未开始和真实流失。手工查询可用；自动分群和消息待做。
经营健康看真实收入、成本、异常付款、退款和未消耗积分负债。净现金收入 − 可归属成本；按档位、模型和资金批次分析。毛利目标 40%。积分成本体系已有；会员分档经营报表待做。

不预设“转化率 10%”或“续费率 80%”等无依据目标。先采集基线、定义观察群体与时间窗口，后续再设目标。避免把全部访问者、当月新增账号和当月到期会员混在同一分母。

09 / 迭代开发路线

每一批交付一个可验收的闭环

批次交付范围完成证据前置条件
P0-A · 本次真实会员概览、暂停展示、未来权益、购买确认与恢复、后台会员与在线付费筛选，非金额文案修正。类型与构建、订单并发和新状态数据库验证、电脑/手机浏览器、公开发布状态记录。沿用现有配置。无需新增预算。
P0-B · 收费上线真实微信收款、到账核对、成本与质量样片、失败退款与财务核对、明确商业售后规则。真实订单和资金账一致，真实供应商样片与可归属成本有证据。支付商户配置、真实验收金额、上线规则 [TBD]。
P1-A · 留存运营全站漏斗、到期与余额提示、用户同意的提醒、分群和套餐经营报表。统计口径与真实数据一致；触达送达、退订和去重验收。邮箱真实送达、触达同意与频率策略。
P1-B · 套餐迁移升级/降级、退款、暂停与补偿、卡密商业证据对接。金额与权益原子变更、冲突恢复、补偿审计和异常订单演练。差价、积分、权益迁移和售后规则先决策。
P2 · 扩展年费、团队工作空间、成员席位、组织权限、企业合同或 API 商业套餐。相应完整业务闭环和成本验收。需求证据与收益模型；年费不能直接乘月费上线。

团队充值套餐的名称不意味着多人协作已经实现；“团队会员”需要组织、作品归属、协作权限、成员退出和预算独立设计。自动续费还需要授权扣款、取消、失败重试、撤销和账单通知完整规则。

10 / 验收与商业上线

界面完成、代码验证与真实收费分别验收

产品与代码

普通、有效、续费、到期、暂停、失败、停售与待确认订单均有清楚反馈。旧套餐配置与旧订单保护保留。

隔离数据库
