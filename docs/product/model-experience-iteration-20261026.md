# 模型体验与全局产品迭代

基线：`5df3bb0`。本轮用户已授权发现产品缺口后直接开发，验证通过后同步 GitHub 与腾讯云。

## 产品判断与执行范围

| 问题 | 对使用的影响 | 本轮改进 |
| --- | --- | --- |
| 模型与中转渠道混淆，原图标根据渠道名推断品牌 | 同一中转渠道中的不同模型显示同一品牌 | 模型名称优先识别，统一矢量小图标、友好名称和原始模型 ID，渠道独立显示 |
| 不同页面的模型选择控件不一致 | 需要反复学习，长名称难读，弹层可能被容器裁切 | 统一搜索选择面板；覆盖创建、内容、资产、分镜、交付及后台配置 |
| 无搜索、收藏或最近选择，缺少键盘操作 | 模型较多时查找困难 | 搜索模型/渠道、收藏、最近选择、键盘方向键与 Enter；弹层复用焦点和滚动管理 |
| UI 会取其他渠道同名模型的价格 | 容易误判积分成本 | 价格按渠道、模型、类型精确匹配；未知、缺价、冲突明确显示，实际费用仍以服务端报价为准 |
| 启用状态被当作可调用状态 | 缺 Key、额度冷却的模型也能被选中 | 区分停用、待配置、冷却、额度不足、配置齐全与连接待确认；不声称已通过供应商实测 |
| 新建内容硬编码 `manjiao/gpt-5.5`，用户无法选择 | 平台已有其他模型也不能在创建前使用 | 新建内容增加文本模型选择，提交真实选择；处理中禁止切换，保留原有失败重试机制 |
| 无集中模型浏览、对比入口 | 创作者难以理解各步骤模型用途 | 增加模型中心、按模态浏览、能力与价格对比；按计费单位展示，不做未经验证的性能排名 |
| 后台渠道和价格分开管理，没有配置缺口视图 | 启用却缺 Key/价格的问题难定位 | 模型目录视图及配置检查，快速进入渠道与价格编辑；所有提示根据实际配置计算 |

前台保持暖白、青绿；后台保留 sub2API 比例、表格与弹窗体系。图标使用内联矢量，不新增远程图片请求。能力说明来自平台配置；名称格式化保留模型原始版本和 ID，不引入未接入的新模型。

## 参考与取舍

- [Runway 官方模型目录](https://dev.runway.com/models/catalog)：参考模型名称、厂商品牌、用途说明和能力分类的信息层级。
- [OpenRouter 官方模型目录](https://openrouter.ai/models)：参考按名称浏览、独立显示厂商及计费单位的方式。
- [sub2API 官方仓库](https://github.com/Wei-Shaw/sub2api)：沿用此前已建立的后台布局与表单视觉。

以上用于交互和信息组织，不移植其模型价格、性能宣传、图片或未接入模型。参考日期：2026-10-26。

## 全局产品中仍需外部条件的事项

QQ 邮箱发信仍需 SMTP 配置与真实收件箱验收；真实支付、付费模型样片质量与费用、外部告警接收渠道仍需相应配置或预算。界面优化和隔离测试不替代这些真实验收。

## 验收要求

精确价格匹配及状态逻辑单元验证；前后台模型选择、搜索、收藏、键盘、嵌套弹窗、长名称、手机及深浅主题浏览器验证；新建内容必须提交用户选择的路由。全量类型、构建和 CI 通过后发布，核对 GitHub/服务器/公开 revision、readiness、公开入口及备份恢复证据。

## 本轮实施与本地验收

八项改进已实现。统一控件覆盖新建漫剧、内容创作、资产、分镜、成片、项目路由编辑，以及后台测试/固定模型/价格策略。充值页和后台评测模型也使用相同名称与图标。后台新增模型目录与配置检查；模型中心支持搜索、收藏及最多三个模型的配置对比。

修复制作页面的跨渠道价格回退和硬编码单价展示，补充模型操作期间的禁用状态，避免成片页轮询重置正在编辑的模型。截图检查额外发现并修复后台嵌套面板层级，回归使用真实鼠标点击验证。

本地全量类型检查与构建通过。共享模块 6 项、前端 247 项、API 94 项、HTTP 传输 5 项通过；API 的 20 项真实集成检查因本机没有相应测试数据库/服务配置跳过。全量桌面/手机浏览器回归 74 项通过，2 项真实登录项目检查因未提供项目地址跳过。新增模型体验回归 8 项覆盖搜索、精确价格、收藏、对比、键盘、嵌套弹窗、所选模型提交和不可用配置阻止创建。
