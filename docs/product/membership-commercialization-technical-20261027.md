# 漫角会员与用户商业化：技术与实施矩阵

日期：2026-10-27。产品行为以同目录 HTML 方案为准。

## 首批边界

本轮补齐会员可见性、当前与未来权益、购买确认、后台商业身份与筛选。沿用现有会员价格、积分、支付、回调幂等、队列和成本毛利保护。未新增数据表或资金迁移；不授予新后台权限、不发放新免费额度、不启用自动扣款。

## 实现矩阵

| 模块 | 代码 | 本轮结果 |

| 会员权益来源 | `apps/api/src/billing/membership.ts` | 已付会员订单作为展示权威；公共条件排除缺失期限、缺失档位、未付与退款订单 |
| 用户概览 | `GET /api/billing/membership` | 保留 `active`、`paidThrough`、`autoRenew:false`；增加 `scheduled`、`scheduledCount`、`lastExpired` |
| 本期权益 | `activeMembership` | 开始包含、结束不包含；按本期已付快照，不以运营套餐当前值代替 |
| 已购到期 | `membershipOverview` | 已付订单的最大到期；不使用可能陈旧的 `UserMembership` 展示缓存 |

共享类型采用向后兼容新增可选字段，前台可接受旧会员概览没有未来字段的响应。后台商业字段缺失时显示“暂未读取”，不假定普通用户或零收入。

## 身份与筛选定义

- `active`：存在 `membershipStartsAt <= now < membershipEndsAt` 的已付完整会员期。
- `scheduled`：没有当前有效期，存在开始与结束都在未来的已付会员期。
- `expired`：存在已结束会员期，且没有任何未结束的已付会员期。
- `none`：没有已付完整会员期。
- `online_paid`：存在 `channel=wechat`、`status=paid`、`amountFen>0` 的订单。
- `no_online_record`：没有上述在线订单。不能据此判定从未现金消费，卡密支付证据不在此汇总。

后台 `onlinePaidCny` 是微信已付订单金额汇总，不是净收入或利润；已退款订单排除，部分退款规则尚未实现。

## 支付与计费保留

1. 原 `requestId` 唯一约束与请求摘要校验继续使用，避免浏览器或网络重试重复下单。
2. 原支付回调锁积分账户、金额验证、交易唯一性、同档延期和快照不变机制保留。
3. 待确认异档订单即使二维码过期仍阻止新档位购买，避免迟到成功回调无法兑现。
4. 原收银区、轮询、订单恢复继续使用；恢复时订单已经支付，也会立即刷新会员和余额，不能遗漏这条成功路径。
5. 已打开页面跨越权益期边界时自动重新读取本期权益；网络失败支持显式刷新恢复。
6. 会员种子文案不覆盖已有运营描述；`SEED_SYNC_EDITABLE_CONFIG=false` 默认保护依旧。此次不运行生产套餐重置。
7. 自动成本计价且毛利保护开启时，任务减免可能受限；页面与购买确认明确按生成前实际报价。
8. 会员展示查询从已付订单读取；会员授予与排程仍保留既有事务缓存机制。本轮没有重写权益授予与资金扣款。
