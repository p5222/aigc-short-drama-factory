## 本轮已修复的十组问题

| 优先级 | 问题与影响 | 最终行为 |
| --- | --- | --- |
| P1 | 成片参数显示新模型，生成仍读取旧项目模型 | 生成前保存当前选择；状态栏区分已保存和待保存；确认信息显示模型、渠道、当前集与参考费用 |
| P1 | 当前集批量生成及失败重试会提交整个项目，范围与页面不一致 | 显式提交当前集镜头 ID；失败重试只取本集失败镜头；最多请求 20 镜，更多镜头保留后续批次 |
| P1 | 存在首帧资产就认为可生成，失败/无地址首帧及运行中视频也计入剩余 | 只接受成功且有可用地址的首帧；运行中视频保留在任务队列，禁止当成新生成提交 |
| P1 | 后端直接取首条价格，类型、单位或重复配置可能导致费用错配 | 前后台共用精确价格检查；文本创建、内容生成、图片及视频计价拒绝冲突和无效单位/单价；显式零价格保留 |
| P1 | 内容分析失败后可重复创建项目，改过参数再重试会与原项目模型不一致 | 保留已确认项目；重试沿用首次意图与参数；保留期间锁定创建表单与模型；新项目仍可从明确入口建立 |
| P1 | 生成成功但刷新失败显示为生成失败，引导再次提交 | 成片新增只刷新恢复状态；分镜刷新前禁止再次生成；内容完成状态与列表刷新分开；保存成功但刷新失败明确说明 |
| P2 | 新建项目依赖硬编码默认渠道/模型，可能默认缺密钥，视频 ID也可能不匹配 | 从真实配置、启用价格和可选择状态计算默认值；保留用户恢复草稿中的选择并提示配置失效 |
| P2 | 后台主要状态遮住其他缺口，已启用却未填写模型的渠道不出现在模型卡中 | 模型同时列出密钥与价格等缺口；无模型渠道显示补充入口；配置问题筛选与数量含义统一 |
| P2 | 桌面窄参数栏把模型与渠道压成省略号 | 按容器宽度换行，名称、渠道、价格分行展示；保留矢量图标及手机布局 |
| P2 | 已保存路由失效后控件仍只显示名称，用户不知为何不能生成 | 所有生成用模型选择控件明确提示停用、缺价、无效价格或配置中不存在；不自动替用户换成另一模型 |

旧 `ProjectWorkbenchPage` 的整段旧工作区已被注释，当前资产和分镜实际使用 `AssetStage`/`ShotStage`。未将不可达旧控件列作现有用户缺陷，也未为这些旧组件重复开发。

## 设计自检

沿用暖白青绿前台和现有 sub2API 后台体系，无新图片生成、无新运行依赖。此次以生成范围、费用和异常恢复为核心，新增文案都帮助用户判断模型是否生效、请求范围以及下一步操作。

| 维度 | 分数 | 依据与边界 |
| --- | --- | --- |
| 可访问性 | 3/4 | 新状态可播报，保留表单标签、按钮禁用、焦点和 Escape 回归；未宣称完整 WCAG AA 认证 |
| 性能 | 3/4 | 保留按页面分包，未加依赖；生产构建通过，未做真实低端手机性能测试 |
| 主题 | 3/4 | 新提示使用已有语义变量，深浅主题回归通过；不是全站逐元素对比度认证 |
| 响应式 | 3/4 | 桌面/手机页面和溢出回归通过，窄栏模型名称完整；物理设备未测 |
| 视觉一致性 | 4/4 | 主观设计判断：沿用品牌、表格与工作区层级，没有引入新的通用装饰模板 |
| 合计 | 16/20 | 已修复本轮可复现的六组 P1、四组 P2 问题 |

有利于保留的既有行为：创建报价与输入绑定、创建请求编号、草稿保护、任务结算、历史导出与当前成片区分、后台统一弹窗和低频轮询。后续每次功能修改继续跑相关回归；外部配置齐备后再执行真实收费与供应商验收。

## 本地验证与发布边界

全量类型检查和生产构建通过。共享模块 8 项、前端 249 项、API 94 项、HTTP 传输 5 项通过。API 的 20 项需要测试数据库/服务的检查因本机未配置而跳过；新增真实数据库价格冲突与冻结回滚场景已加入相应用例，但本机未执行。

完整浏览器回归 88 项通过、2 项因未提供真实登录项目地址跳过。新增 14 项（七个场景×桌面/手机）覆盖模型保存顺序、当前集范围、只刷新恢复、可用默认模型、原参数重试、列表刷新失败、后台同时缺密钥/价格、20 镜上限以及无效单位阻断；部分场景在同一用例内联验收。

本轮没有远端 CI、GitHub 推送或生产部署证据。GitHub 服务此前重新授权返回明确要求：`Start a new conversation before retrying this service`。需真正新建对话继续发布；已有发布授权不变。生产 QQ 邮箱 SMTP、真实支付及付费样片验收仍需要相应配置或预算。
