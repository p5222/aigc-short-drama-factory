# 分镜与视频生成交互对标记录

更新时间：2026-06-27

## 对标来源

- U 漫剧公开页：定位为“小说改编、分镜生成、成片合成”的一站式 AI 漫剧创作云，强调剧本、角色、镜头、配音字幕与成片统一完成。参考：https://ai.gitaaa.com/pc
- Toonflow-app：开源项目强调“策划 → 编剧 → 分镜 → 出片”闭环、无限画布生产工作台、三层 Agent、可编程供应商系统、章节事件图谱、Skill 文件化提示词。参考：https://github.com/HBAI-Ltd/Toonflow-app
- Boords AI Storyboard Generator：强调脚本转分镜、镜头列表、镜头级评论/状态、角色一致性、Animatic 和导出。参考：https://boords.com/ai-storyboard-generator
- Storyboarder：强调快速添加 board、右侧维护 dialogue/action/timing/shot type 元数据、制作 animatic。参考：https://wonderunit.com/storyboarder/
- Runway Image to Video：强调从静态图片生成视频片段，和本项目“分镜图作为首帧 → 图生视频”的后续链路一致。参考：https://runwayml.com/ai-tools/image-to-video/

## 对标结论

1. 分镜生成结果不能作为普通素材瀑布流展示。角色、场景、道具属于素材库；分镜图和视频草稿必须按镜头顺序组织。
2. 分镜编辑区应以“镜头卡片”为核心，一张卡包含首帧、镜头号、时长、景别、机位、运镜、角色、站位、台词/旁白、音效、图片提示词、视频提示词、生成状态。
3. 图片生成页可以更像画廊，但仍然必须保持镜头编号顺序，不能只按上传/生成时间排序。
4. 视频生成页应提前设计成“时间线”，以分镜图作为首帧，展示时长、运镜、动作、视频提示词和生成状态。
5. 角色一致性不只靠提示词，需要角色卡、稳定 seed、负面提示词、参考资产和镜头引用链路共同实现。

## 当前实现尺寸

当前验证视口：1280 × 720，左侧 SaaS 导航宽 230px，主工作区约 937px。

- 镜头导演台：单镜头卡约 937 × 392。
- 导演台首帧：9:16 项目固定约 180 × 320，右侧展示参数和提示词。
- 分镜图画廊：4 列，单张竖图预览约 222 × 394，整卡约 224 × 549。
- 视频时间线：单行约 937 × 241，首帧约 96 × 171。
- 画幅规则：`9:16`、`16:9`、`1:1` 均用 CSS ratio class 自动切换。

## 后续排期建议

1. 增加单镜头重生成接口：按 `shotId` 单独重新生成分镜图，支持失败重试和局部迭代。
2. 增加视频 Provider 表：将 Runway/可灵/即梦/通义/中转站视频模型统一为可插拔接口。
3. 增加镜头详情抽屉：支持编辑图片提示词、视频提示词、角色引用和模型参数。
4. 增加版本管理：同一镜头保留多张候选图和多个视频草稿，支持选为最终版。
5. 增加批量导出：导出 Excel 分镜表、图片 zip、视频草稿清单和成片合成任务。
