# 漫角后台 Design Mode 与简化约束

更新时间：2026-06-30

## 1. 后台设计模式

后台管理系统统一参考 sub2api 的清晰控制台风格：白色侧栏、浅青蓝背景、顶部固定信息栏、指标卡、筛选条、数据表、行内操作。

核心原则：

- 每个模块是一页，不做长瀑布。
- 数据管理优先使用表格，不用大卡片堆叠。
- 高频操作放在每行最右侧，例如保存、启停、测试、入账。
- 页面顶部只放当前模块标题、说明、刷新、成本或余额信息。
- 筛选条件横向排列：搜索、类型、状态、时间范围。
- 内容区保持高密度但留白清晰，避免营销页风格。

## 2. 后台模块布局规范

### 运营总览

- 顶部四个指标卡：用户、项目、成功率、启用渠道。
- 下方展示平台规则和计费策略，不展示长篇说明。
- 作用是快速判断系统是否健康。

### 用户积分

- 表格字段：用户、角色、余额、冻结、累计充值、累计消耗、项目数、状态、人工调整。
- 支持行内改名、改角色、改状态、人工加减积分。
- 人工调整必须写入积分流水。

### 兑换码

- 批量生成区横向排布：活动名、前缀、积分、份数、生成按钮。
- 兑换码列表改为表格：code、活动名、积分、使用次数、批次、状态、创建时间、操作。
- 每个 code 必须唯一，默认单个 code 只可兑换 1 次。
- 不再使用大方块卡片展示兑换码。

### 套餐会员

- 用表格管理充值包：套餐名、售价、到账积分、赠送积分、标签、卖点、状态、操作。
- 前台只展示启用套餐。

### 订阅会员

- 用表格管理会员包：会员名、月费、月额度、折扣、队列等级、权益、状态、操作。
- 不做无限量会员，只做月额度和折扣权益。

### 模型路由

- 用表格管理供应商：供应商、类型、模型、Base URL、能力、状态、操作。
- API Key 不在前端暴露，仍从服务器环境变量读取。
- 行内支持保存、启停、测试文本/图片/视频连接。

### 智能体工厂

- 保留两个核心 Agent：
  - 长篇网文辅助创作 Agent。
  - 角色一致性生成 Agent。
- 输出结构必须可审查，不直接堆一个黑箱聊天框。

### 价格策略

- 用表格管理：供应商、模型、类型、单位、积分单价、成本、状态、操作。
- 生成任务优先读取启用价格。

### 提示词模板

- 用表格展示：模板、类型、版本、摘要、状态。
- 后续再扩展版本管理、灰度和回滚。

## 3. 项目简化约束

为了避免项目越来越臃肿，后续开发必须遵守：

- 一个业务入口只保留一个主要流程，不同时保留多个重复入口。
- mock 只能作为显式 provider 存在，真实 provider 失败不能自动假成功。
- 旧测试数据、旧启动脚本、临时日志不能长期留在根目录。
- 前台生产台只保留五个核心区：角色定稿、镜头编辑、分镜预览、视频导出、分镜表。
- 后台模块都使用同一套筛选条和表格样式，除运营总览和 Agent 预览外，不新增大块卡片。
- 每个新增 provider 必须同时有：
  - provider 配置。
  - 价格策略。
  - 后台测试入口。
  - 失败原因透出。
- 每个新增资产生成能力必须真实落库，并能在前端看到结果。

## 4. 当前本轮后台 UI 变化

- 后台整体改为 sub2api 风格浅色控制台。
- 侧栏改成白底、图标菜单、底部模式/返回入口。
- 顶栏改成标题、通知、语言、成本胶囊、用户信息。
- 兑换码批量生成改为横向条。
- 兑换码、套餐、会员、模型、价格、模板都改成表格管理。
- 用户积分支持表格行内编辑和人工入账。
- 模型路由支持表格内保存、启停、测试。
- 智能体工厂保留双卡预览，但输出结构更清晰。
