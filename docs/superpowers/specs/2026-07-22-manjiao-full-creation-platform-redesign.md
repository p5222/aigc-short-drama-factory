# 漫角全流程创作平台整体重构规格

日期：2026-07-22
状态：待用户确认

## 1. 目标

将现有项目从“多个生成页面和提示词拼接”重构为一套可从同类小说创作完整运行到视频导出的生产系统。重构必须保留现有用户、项目、积分、任务、作品、模型路由和创作现场数据，最终一次性切换生产版本，不部署半成品。

成功标准：

1. 用户可以从参考小说、原创灵感或已有小说开始创作。
2. 系统可以依次完成爆款结构分析、章节策划、正文创作、剧本改编、实体提取、资产生成、分镜、首帧、视频、配音字幕和导出。
3. 所有生成阶段使用正式版本化提示词，能通过 PromptVersion 和 ExperimentRun 对比模型及提示词效果。
4. 深色和浅色主题使用同一组件结构，所有文字、边框、选中态和禁用态清晰可读。
5. 现有真实模型、计费、任务和数据持久化链路继续有效，不增加假按钮或 Mock 主流程。

## 2. 产品信息架构

左侧导航重构为：

```text
创作
- 工作台
- 内容创作
- 新建漫剧
- 我的作品

生产
- 剪辑中心
- 生成队列

账户
- 我的
- 积分充值
- 积分明细
- 帮助中心
```

“内容创作”负责小说与剧本，“新建漫剧/项目工作台”负责视觉生产。两个模块通过正式项目版本连接，不把长篇写作和媒体生成塞进一个页面。

## 3. 内容创作模块

### 3.1 创建入口

提供三种模式：

1. 同类创作：导入 1-3 篇参考作品，提取共同爆款结构后生成原创作品。
2. 灵感原创：输入题材、人物关系、核心冲突和目标平台。
3. 小说改编：导入已有小说，直接进行章节解析和剧本改编。

### 3.2 工作流

```text
素材输入
→ 爆款结构分析
→ 创作策略
→ 章节大纲
→ 分章正文
→ 剧本改编
→ 人物/场景/道具提取
→ 确认生产版本
→ 进入视觉工作台
```

每一步必须保存输入、输出、PromptVersion、模型、运行参数和用户选定版本。用户可以重跑当前步骤，但下游已确认版本不能被异步旧结果覆盖。

### 3.3 页面布局

- 左侧：章节/版本列表，展示状态和字数。
- 中间：主编辑区，支持原文、输出和差异视图。
- 右侧：当前步骤配置、风格、模型、版本与评测摘要。
- 顶部：作品标题、保存状态、流程进度和“确认进入下一步”。
- 底部不设置长期占位的大按钮区，操作跟随当前内容上下文。

## 4. 领域模型

新增或整理以下领域对象：

- `ContentProject`：内容创作项目，可在确认后绑定生产 Project。
- `SourceDocument`：参考小说、已有小说和灵感输入。
- `StoryAnalysis`：爆款开头、高潮、反转、爽点、共同结构、风险。
- `StoryOutline`：作品总纲、章节大纲、每章目标和钩子。
- `StoryChapter`：章节正文及版本。
- `ScriptVersion`：可生产剧本版本。
- `EntityCatalog`：人物、场景、道具的规范化主数据。
- `StyleProfile`：风格分区、视觉规则、人物/场景/镜头规则和负面规则。
- `PromptDefinition`：稳定提示词标识。
- `PromptVersion`：系统提示词、用户模板、输出 Schema、版本状态。
- `ExperimentRun`：样本、模型、提示词版本、参数、输出、耗时、成本和评分。

生产 Project 继续承担角色资产、场景资产、分镜、视频、音频、字幕和导出任务。

## 5. 提示词系统

主提示词定义：

```text
hit_story_analysis
same_genre_story_strategy
chapter_outline
chapter_generation
novel_to_script
entity_extraction
character_identity_board
scene_environment_sheet
storyboard_core
storyboard_video_seedance_15s
storyboard_video_doubao_10s
```

每个版本保存：

- systemPrompt
- userTemplate
- variableSchema
- outputSchema
- validationRules
- negativeRules
- providerOverrides
- status: draft / active / archived

业务代码只按定义 ID 请求激活版本，不再把长提示词散落在生成器和数据库文件中。生成任务保存完整 promptSnapshot，确保历史可复现。

## 6. 风格系统

将 Excel 中四个分区和全部风格导入 StyleProfile。用户选择后形成不可含糊的统一档案：

```json
{
  "name": "",
  "category": "",
  "summary": "",
  "characterRules": [],
  "sceneRules": [],
  "lightingRules": [],
  "cameraRules": [],
  "materialRules": [],
  "negativeRules": []
}
```

剧本阶段只使用风格的题材表现边界；人物、场景和媒体生成使用完整视觉档案。风格不能改写剧情事实。

## 7. 视觉生产工作台

保留四个生产阶段：

```text
内容 → 资产 → 镜头 → 成片
```

### 内容

展示已确认剧本、集/场结构、人物和场景索引。剧本正文不再和镜头编辑混杂。

### 资产

左侧使用“人物 / 场景 / 道具”分段列表；中间展示大图与版本；右侧编辑结构化属性和生成配置。人物主资产为身份板，场景主资产为四视图空间板。

### 镜头

左侧镜头列表，中间首帧/视频画布，右侧镜头语言、动作、对白、声音和模型设置。角色、场景通过真实 assetId 引用。

### 成片

使用可读尺寸的片段列表、视频监看区、只读或受能力开关控制的时间线、配音字幕和导出。连续播放使用真实视频时长并自动播放下一条可用片段。

## 8. 主题和设计系统

重建语义令牌：

```text
page / surface / elevated / canvas
text-primary / text-secondary / text-muted / text-inverse
border / border-strong
accent / accent-hover / accent-selected
success / warning / danger / info
disabled-surface / disabled-text
shadow-low / shadow-high
```

规则：

1. 深浅色共用 DOM 和尺寸，不以主题选择不同组件。
2. 媒体画布允许深色，但必须通过工具栏、边界和背景层级与页面自然衔接。
3. 不使用全局 `!important` 堆叠修复主题。
4. 不新增玻璃、发光球、装饰渐变和卡片嵌套。
5. 图标使用现有 Lucide；ImageGen 仅生成设计稿和必要的真实视觉资产，不生成 UI 内文字图标。
6. 逐页检查登录、首页、内容创作、创建项目、四阶段工作台、任务中心、作品库、账户页和后台。

## 9. 视觉方向

采用“专业制作台”方向：

- 浅色：冷白页面、白色表面、石墨文字、青绿色操作色，边界清楚但不阴影泛滥。
- 深色：中性石墨背景、略浅表面、近白文字、同一青绿色操作色。
- 信息密度偏高，使用列表、分段控制、表格和稳定三栏布局，不使用营销式大卡片。
- 首页工作台突出最近作品、当前任务和继续生产，不重复解释产品功能。

ImageGen 阶段生成三张 2K 静态设计参考：内容创作、资产阶段、镜头阶段；选用同一视觉语言后实现真实组件。

## 10. 真实调用与任务系统

所有生成请求必须：

1. 解析用户选择的模型和 StyleProfile。
2. 获取对应 PromptVersion。
3. 创建 GenerationTask 并冻结预估积分。
4. 调用真实上游。
5. 持久化输出和 promptSnapshot。
6. 按实际成功结果扣费，失败解冻。
7. 更新 ExperimentRun 和阶段评测数据。

长篇生成按章节执行，不请求模型一次输出两万字。每章保存独立版本，并支持从失败章节续跑。

## 11. 连续性策略

- 人物一致性：角色身份板 + 上传参考 + stable seed + 资产 ID。
- 场景一致性：场景四视图 + 固定空间锚点 + 场景 ID。
- 镜头一致性：screen-left/center/right、前中后景、180 度轴线。
- 视频一致性：上一镜尾帧可作为下一镜首帧参考；不使用破坏性遮脸方案作为默认流程。
- 声音一致性：角色 voiceProfile 绑定专属音色和参考音频。

## 12. 迁移与兼容

1. 新表通过增量迁移创建，不删除现有表。
2. 现有 Project 自动映射为“已进入生产”的项目。
3. 现有 character、asset、storyboard 和 task 数据原样保留。
4. 旧提示词字段继续可读，新任务使用 PromptVersion 快照。
5. 切换前生成数据库、storage、source 和 web-dist 备份。

## 13. 错误处理

- JSON 输出必须进行 Schema 校验和一次受控修复。
- 缺少实体引用时阻止媒体生成，并指出缺失的人物或场景。
- 模型失败、内容安全拒绝、余额不足、队列超时和持久化失败分别展示。
- 异步结果使用 operationId 防止旧请求覆盖新版本。
- 批量任务展示真实成功、失败和待处理数量。

## 14. 验证与发布

开发期间按模块验证，生产只在全部通过后统一切换。

完整上线门禁：

- 提示词模板和 Schema 单测。
- 内容创作版本、实体归并和异步竞争测试。
- 计费、任务、模型路由和数据库集成测试。
- Web/API/shared 类型检查和构建。
- 深浅色关键页面桌面及移动截图检查。
- 真实测试项目从内容输入跑到至少一个可播放视频和导出任务。
- 生产备份、部署、三域名健康检查和资源指纹确认。

后续小改按风险缩减门禁：纯提示词/CSS 只跑相关测试、类型检查、构建和健康检查；数据、计费、任务和模型链路仍跑完整相关测试。

## 15. 不在本次范围

- 多管理员权限体系。
- 多人实时协作。
- 完整非线性专业剪辑器。
- 自动发布到第三方短视频平台。
- 用评测结果阻止创作者发布。

评测只用于指出哪个阶段需要优化，不作为发布门禁。

## 16. 后台管理系统整体重构

### 16.1 目标

后台继续采用 Sub2API 的克制型运营后台语言：固定侧栏、薄顶栏、紧凑筛选区、数据表格、状态标签和抽屉式编辑。不能只复刻颜色和圆角，必须补齐每个模块的业务对象、状态流转、筛选、批量操作、详情和审计信息。

视觉基准：

- 白色或低对比中性页面，不使用大面积青色渐变背景。
- 8px 以内圆角，表格优先，统计卡只展示真正需要对比的核心指标。
- 操作列使用图标或短命令；删除、停用等危险操作使用二次确认。
- 表格拥有固定表头、分页、空状态、加载态、错误态和筛选回显。
- 深浅色共用布局与组件，深色只替换语义颜色。

### 16.2 后台信息架构

```text
核心运营
- 运营总览
- 用户管理
- 平台公告
- 创作现场管理
- 创作质量中心

商业化
- 兑换码
- 套餐会员
- 订阅会员
- 积分与账单

模型与生产
- 模型路由
- 价格策略
- 提示词版本
- 实验评测
- 生成任务

系统
- 内容安全与失败记录
- 系统设置
```

### 16.3 模块闭环

#### 运营总览

展示真实用户、项目、生成任务、积分收入/消耗、失败率、模型成本和创作漏斗。指标可跳转到对应过滤后的明细页，避免“只有数字不能处理”。

#### 用户管理

支持关键词、状态、注册时间、套餐和余额筛选；查看用户项目、任务、积分流水和登录状态；允许充值、停用和恢复。单管理员场景不增加角色权限配置。

#### 创作现场管理

展示真实提交作品，支持待审核、已通过、已拒绝、草稿和精选状态；审核抽屉中直接预览封面/视频、创作者和来源项目；通过后进入前台，拒绝必须填写原因。

#### 创作质量中心

按内容、资产、分镜、视频和成片阶段聚合评分与失败原因，回答“哪个模块需要优化”。可进入单项目质量时间线，不作为发布门禁，不生成任务指派。

#### 兑换码

采用 Sub2API 式筛选与表格：批次、类型、面值/次数、状态、使用者、使用时间、过期时间。支持批量生成、批量停用、导出和单条详情；行内编辑只用于低风险字段，其他编辑进入抽屉。

#### 套餐、订阅和积分

统一商品、权益、价格、有效期、上架状态和订单数据。前台展示内容必须来自这里，禁止前后台各自维护一份商品文案。

#### 模型路由

按能力展示文本、图片、视频、TTS 模型；支持供应商、模型池、优先级、故障转移、可用状态和测试结果。生成前用户可选择的模型必须来自已启用路由，并使用价格策略计算积分。

#### 价格策略

按 provider + model + size/quality/duration 保存精确价格。展示受影响的前台生成入口，并在修改前预览计费变化。

#### 提示词版本

管理 PromptDefinition 和 PromptVersion；展示系统提示词、用户模板、变量 Schema、输出 Schema、状态和变更说明。激活新版本前进行样本测试，不直接覆盖历史快照。

#### 实验评测

创建模型、提示词或组合实验，选择样本集和评价维度；分页展示每个样本的输入、输出、耗时、成本和评分。支持人工选优，并将结果汇总为待处理的优化建议，不创建指派工单。

#### 生成任务

按任务类型、模型、状态、项目和时间筛选；展示冻结积分、实扣积分、上游 taskId、重试次数和失败分类。只对可重试任务提供重试，不伪造成功状态。

### 16.4 后台页面模板

后台页面统一使用五类模板：

1. 总览：核心指标 + 趋势/漏斗 + 异常列表。
2. 列表：标题 + 筛选工具栏 + 表格 + 分页。
3. 主从：左侧状态/分组列表 + 右侧表格或详情。
4. 配置：分段表单 + 影响预览 + 保存/测试。
5. 评测：样本列表 + 双结果对比 + 评分与结论。

不允许每个模块自行发明卡片、边距、按钮和状态颜色。

### 16.5 后台真实数据和审计

- 所有统计使用数据库分页聚合，不把全量数据读入内存。
- 变更保存操作者、时间、变更对象和前后摘要；当前只有一个管理员，不做复杂授权。
- API 的筛选、排序、分页和前端表格保持同一契约。
- 空结果、加载失败、权限失败、上游测试失败和保存冲突分别展示。
- 兑换码、余额、价格和模型路由变更必须使用事务。

### 16.6 后台视觉设计稿

ImageGen 生成三张 2K UI 设计参考：

1. 运营总览与创作质量漏斗。
2. Sub2API 风格的兑换码/用户密集表格页。
3. 提示词版本与实验评测对比页。

设计稿只决定层级、密度、配色和布局；文字、图标、表格和交互全部使用真实前端组件实现，减少 SVG 和图片文字。
