# 漫剧正式项目与视频分镜生产流程设计

## 目标

把现有漫剧制作 Skill 转换成项目内可执行、可保存、可续跑的生产流程；将《北境婚书》完整导入为正常项目数据，而不是只读示例；让其他小说也能沿同一流程完成小说改编、分集剧本、资产、分镜和视频提示词生产。

## 已确认规则

- 《北境婚书》作为正式项目导入数据库，出现在正常项目列表并支持编辑、重生、质检和继续生产。
- 小说改编基准为约 20,000 个有效中文字符对应一集约 180 秒漫剧；这是原小说素材预算，不是最终剧本字数。
- 默认忠实改编，不允许为了增加集数自动扩写。
- 用户可选择生成接下来 1、2、3……集或全部剩余集；已完成第 1–3 集后选择 2 集，应生成第 4–5 集。
- 已完成剧集支持单集重新生成，新版本保留历史记录。
- 即梦 15 秒与豆包 10 秒是互斥的项目级生产规格，由用户按需求选择，也允许后续明确切换并生成新的分镜版本。
- 角色、场景、道具生成完成后回写项目资产库，后续分镜通过稳定资产 ID 引用。
- 视频分镜必须包含首帧、尾帧、边界类型和连续性状态，不能只保存一段自然语言提示词。

## 范围

### 本期范围

1. 《北境婚书》正式项目导入。
2. 小说来源的集数预算与语义分集。
3. 逐集剧本持久化、增量生成与单集重生成。
4. 角色、场景、道具的正式资产化及图片回写。
5. 即梦 15 秒和豆包 10 秒两套可选分镜规格。
6. 首尾帧、连续性和视频提示词的结构化保存。
7. 失败重试、断点续跑和阶段状态展示。

### 暂不纳入

- 为超过建议集数的目标自动扩写剧情。
- 在没有可用视频供应商时宣称已经生成成片。
- 一次模型调用直接完成整季全部生产。
- 将《北境婚书》放入独立案例页面或旁路存储。

## 总体架构

采用“正式项目 + 持久化工作流编排”。Skill 提供领域规则和提示词模块，数据库保存生产状态，现有模型适配器和生成队列执行单个阶段。

```text
小说 / 已有剧本 / 已完成制作包
  -> ContentProject（内容来源与改编过程）
  -> ProductionEpisode（逐集规划与剧本版本）
  -> Project（漫剧制作项目）
  -> Character / Asset（角色、场景、道具和参考图）
  -> Storyboard（10 秒或 15 秒视频片段）
  -> GenerationTask（图片、首尾帧和视频生产任务）
```

`ContentProject.productionProjectId` 继续作为内容项目和制作项目的连接，但交接改为幂等同步：同一内容项目重复交接时更新关联制作项目，不创建第二份脱离来源的数据。

## 数据模型

### 逐集生产实体

新增逐集实体，避免继续把整季剧本塞入单个 `ScriptVersion.content`：

- `ProductionEpisode`
  - `contentProjectId`
  - `productionProjectId`
  - `episodeNo`
  - `title`
  - `sourceStart` / `sourceEnd` 或来源章节引用
  - `sourceCharacterCount`
  - `targetDurationSeconds`
  - `status`
  - `activeScriptVersion`
- `EpisodeScriptVersion`
  - `episodeId`
  - `version`
  - `content`
  - `structuredResult`
  - `promptSnapshot`
  - `status`

每个项目内 `episodeNo` 唯一；重生成增加版本，不覆盖旧版本。

### 生产规格

制作项目保存：

- `segmentProfile`: `jimeng_15s` 或 `doubao_10s`
- `episodeDurationSeconds`: 默认 180，可由项目明确调整
- `sourceCharactersPerEpisode`: 默认 20000
- `allowExpansion`: 固定为 `false`

切换生产规格不会覆盖旧分镜，而是创建新的分镜版本；当前版本由项目指向。

### 分镜连续性

扩展分镜数据：

- `segmentProfile`
- `sequenceNo`
- `startSeconds` / `endSeconds`
- `boundaryType`: `CONTINUE`、`CUT_MATCH`、`CUT_SCENE`
- `startState` / `endState`
- `firstFramePrompt` / `lastFramePrompt`
- `firstFrameAssetId` / `lastFrameAssetId`
- `continuitySourceShotId`
- `promptVersion`

只有 `CONTINUE` 自动复用上一镜审核通过的尾帧；`CUT_MATCH` 使用独立匹配首帧；`CUT_SCENE` 创建新场景建立帧。

## 集数预算与增量生成

### 小说

1. 统计去除空白和格式标记后的有效字符数。
2. 计算基础预算 `ceil(effectiveCharacters / 20000)`。
3. 识别原文章节、场景、时间跳转、剧情转折和结尾钩子。
4. 在不超过基础预算的前提下调整语义边界；短尾段优先合并，禁止从句子或场景中间切断。
5. 用户只能选择 1 到建议上限或全部剩余集。

已有明确“第 N 集”的剧本以剧本集数为上限；只有场次的剧本按场次和目标时长规划，但不新增剧情。

### 生成范围

- 首次选择 N 集：生成第 1 到 N 集。
- 已完成 K 集后选择 N 集：生成第 K+1 到 `min(K+N, maxEpisodes)` 集。
- “全部剩余”：生成所有未完成集。
- 单集重生成：只为指定集创建新剧本版本，其余剧集不变。
- 队列按单集建立任务；失败只重试失败集，不重复已完成集。

## 小说到剧本

每集先保存来源范围和不可删除剧情节点，再生成约 180 秒的可视化剧本。剧本必须包含场景、人物、动作、对白、旁白、声音和预计秒数；总时长按节奏校验，而不是用最终剧本文字数推算。

20,000 字小说到 180 秒视频意味着大幅改编压缩，因此必须保留主冲突、关键因果、人物关系变化和结尾钩子，同时删除重复说明和不可视化叙述。任何事实改写或新增剧情均判为失败。

## 资产生产

剧本确认后提取角色、场景和道具，创建稳定 ID。导入已有资产时优先使用源文件中的 ID；新项目使用项目级确定性 ID。

资产状态为：`draft -> prompt_ready -> generating -> review -> approved / failed`。图片生成完成后写入 `Asset.referenceUrl` 或对象存储地址，并更新角色的 `referenceAssetId`。未审核资产可以测试生成，但不能自动作为整季连续性基准。

## 视频分镜规格

### 即梦 15 秒

- 每段最长 15 秒，180 秒约 12 段。
- 默认时序为 0–4、4–8、8–12、12–15 秒，可按内容微调。
- 末段必须形成可审核尾帧。

### 豆包 10 秒

- 每段最长 10 秒，180 秒约 18 段。
- 默认时序为 0–3、3–7、7–10 秒，可按内容微调。
- 末段必须形成可审核尾帧。

两套规格共用同一个结构化分镜合同，只由 profile 决定片段时长、时序模板和供应商约束。用户在项目设置中选择一种规格后生成对应版本。

## 提示词治理

用户提供的两份指令作为规则来源，但不原样内置示例。现有示例出现“机场剧情生成教室递笔”的内容污染，因此生产模板只保留规则，并通过结构化字段渲染：

- 当前剧本是剧情、动作和对白的唯一来源。
- 上一镜结束状态和下一镜需求作为连续性上下文。
- 角色、场景和道具由稳定资产 ID 注入。
- 禁止字幕、水印、Logo 和剧本外内容。
- 执行内容安全词与语义检查，但不得通过替换词改变剧情事实。
- 提示词模板保存版本和快照，便于回归与重生成。

## 《北境婚书》导入

导入工具读取项目导航并验证下列完整性：12章正文、12集剧本、6个角色、18个场景、10个道具、12集分镜和12集即梦提示词。DOCX 正文通过结构化文档解析器读取，Markdown 用于剧本、资产和分镜结构解析，PNG 复制到项目对象存储或受管理资源目录。

导入采用固定 `importKey` 和事务：

1. 创建或查找内容项目。
2. 写入12章来源和12个逐集剧本版本。
3. 创建或更新关联制作项目。
4. 写入角色、场景、道具及参考图。
5. 写入已有分镜和即梦提示词。
6. 保存导入报告，包括成功数、缺失项和无法解析项。

重复执行同一 `importKey` 时更新同一项目；不得重复创建。《北境婚书》现有60个分镜仅作为已完成的压缩分镜版本，界面明确提示正式180秒成片仍需扩充分镜。

## 用户界面

- 新建项目：展示根据来源计算的建议集数和剩余集数。
- 生成范围：`生成接下来 1 集` 到 `生成接下来 N 集`，最后一项为 `生成全部剩余 N 集`。
- 剧集列表：显示来源范围、剧本状态、版本和“重新生成本集”。
- 资产阶段：角色、场景、道具分组审核和生成。
- 分镜阶段：项目级切换即梦15秒或豆包10秒；切换前说明将创建新版本。
- 分镜卡片：同时展示镜头内容、首尾帧、边界类型、连续性来源和任务状态。

## 错误处理与恢复

- 每集、每项资产、每个分镜片段分别建队列任务。
- 阶段输出先做结构验证，再事务写入数据库。
- 网络或并发错误可重试当前任务；内容校验失败返回可读原因，不自动吞掉。
- 页面刷新、离开工作台或换设备后，从数据库读取任务状态继续。
- 重新生成不覆盖已确认版本；用户可切回历史版本。

## 验收标准

1. 《北境婚书》出现在正常项目列表，能进入内容创作和制作工作台。
2. 12章、12集剧本、资产、已有分镜和提示词均可查看且相互关联。
3. 普通小说按20,000有效字符/集计算建议上限，并按语义边界分集。
4. 集数选择提供1到剩余上限及全部剩余，增量生成不重复已有集。
5. 超过建议上限不可选择，系统不自动扩写。
6. 角色、场景和道具生成结果回写资产库，分镜引用稳定资产 ID。
7. 用户可选择即梦15秒或豆包10秒，系统只生成所选规格的当前分镜版本。
8. `CONTINUE`、`CUT_MATCH`、`CUT_SCENE` 按规则处理首尾帧，不跨场景错误复用尾帧。
9. 给定机场剧情时，生成结果不得出现示例中的教室、班长或递笔内容。
10. 任一单集或单镜失败后可独立重试，已完成数据不重复生成。

## 后续智能体

本流程跑通后，再将其包装为“漫剧制作总监 Agent”。Agent 只负责理解目标、选择工具、检查缺失条件和推进阶段；所有正式成果仍通过上述实体、队列和审批状态保存，避免把整季结果留在一次对话中。
