# 首页 4K 卡片交互与浅色主题重构设计

日期：2026-07-10

## 1. 目标

本次迭代解决以下问题：

1. 首页收拢状态只看到一张卡，卡片过大且位置偏上、偏右。
2. 卡片展开后视觉层互相遮挡，用户无法稳定点击并切换视频。
3. 当前卡片只显示海报，不能跟随主背景播放。
4. 现有轻量视频清晰度不足，需要恢复 CineArt 对标站的五条原始 4K 视频。
5. 登录后的前台浅色系统存在白底低对比、状态色不统一和层级不清的问题，需要统一为后台 Sub2API 风格。

## 2. 已确认决策

- 卡片收拢布局采用 **B1 紧凑偏左方案**。
- 卡组整体缩小并进一步移动到左下方。
- 收拢时主卡居中，每侧露出两张卡，单层可见宽度约 18-22px。
- 当前主卡跟随背景视频播放，其他四张暂停并仅预载元数据。
- 第一轮采用 **方案 1：直接复刻 CineArt 的 4K 视频结构**。
- 保留 `4k / 2k / fast` 媒体档位开关，便于快速回退。
- 浅色系统采用 **A：Sub2API 青绿中性主题**。
- 如果直接 4K 方案在真实网络验证中不合格，再切换为“轻量首播、4K 后台升级”的方案 2。

## 3. 非目标

- 不改首页品牌文案和登录流程。
- 不重做深色主题。
- 不改创作现场、审核系统和作品数据库流程。
- 不引入 HLS、DASH 或新的流媒体服务。
- 不让五张卡片同时播放；这会恢复多路并发解码问题。

## 5. 媒体架构

### 5.1 媒体档位

场景数据从单一 `videoUrl` 扩展为三档：

- `video4kUrl`：本次提取的原始 4K 文件。
- `video2kUrl`：现有 2K 备用文件。
- `videoFastUrl`：现有 1080p FastStart 备用文件。

`VITE_CINE_MEDIA_TIER` 支持 `4k`、`2k`、`fast`。生产第一轮默认 `4k`。

### 5.2 背景双缓冲

首页继续保留两个背景 `<video>`：

- 当前槽位播放活动场景。
- 隐藏槽位预加载下一场景。
- 新场景达到可绘制状态后才交叉淡入。
- 切换完成后暂停并释放旧槽位。

4K 在 8 秒内无法提供可绘制帧，或触发 `error/stalled` 时，当前场景按 `4k -> 2k -> fast` 自动降级。降级期间保留上一条视频或海报，不显示黑屏。

### 5.3 卡片视频

五张视觉卡各保留一个 `<video>`，但运行规则严格限制：

- 仅活动主卡使用 `preload="auto"` 并播放。
- 其他四张使用 `preload="metadata"`、保持暂停，并显示首帧或海报。
- 卡片切换后，旧卡立即暂停，新主卡对齐当前背景后播放。
- 卡片视频与背景使用同源 URL，使浏览器可以复用网络缓存。

### 5.4 播放同步

活动背景是时间基准。同步以下事件：

- `play`：播放活动卡片。
- `pause`：暂停活动卡片。
- `seeking/seeked`：设置卡片 `currentTime`。
- `ratechange`：同步 `playbackRate`。
- `ended`：同步循环或进入下一场景。

使用 `requestVideoFrameCallback` 检查活动背景和活动卡片的时间差；差值超过约 120ms 时校正，正常范围内不频繁 seek，避免抖动。

## 6. 卡片布局与交互

### 6.1 收拢状态 B1

- 主卡尺寸固定为当前实现的 80%。
- 桌面卡组目标边距为左侧 24-40px、底部 24-40px，并保持在安全区内。
- 左右各露出两张卡，单层目标可见宽度为 20px，响应式允许 18-22px。
- 相邻卡保持轻微旋转和纵向错位，远端卡透明度降低但仍可辨识。
- 移动端不依赖 hover，保留主卡、侧边切换按钮和卡片点击能力。

### 6.2 展开状态

- 鼠标进入卡组后扇形展开。
- 五张卡保持稳定尺寸，不因活动标签或视频加载改变布局。
- 展开间距保证每张卡至少存在一块不被其他卡覆盖的可点击区域。
- 鼠标离开卡组后恢复 B1 收拢状态。

### 6.3 点击命中

视觉卡和点击命中层分离：

- 视频、遮罩、扫描线和装饰角统一 `pointer-events: none`。
- 独立的五个语义按钮负责点击、键盘焦点和 `aria-pressed`。
- 收拢状态的侧卡按钮只占用对应的可见窄边，主卡按钮占用主卡主体。
- 展开状态的按钮随卡片位置移动，覆盖各自完整可见区域。
- 点击侧卡后立即进入活动状态，并请求对应背景；视频首帧未就绪前保留旧背景。
- 支持左右方向键选择，Enter/Space 确认切换。

## 7. 浅色主题系统

### 7.1 样式边界

新增独立浅色主题样式文件，由入口在基础样式之后加载。浅色主题通过 `:root[data-theme="light"]` 生效，不影响首页电影感登录页和深色主题。

### 7.2 语义色

| Token | 值 | 用途 |
| --- | --- | --- |
| `--light-page` | `#f6f9fb` | 页面背景 |
| `--light-surface` | `#ffffff` | 主面板、弹窗、表格 |
| `--light-subtle` | `#f8fbfd` | 次级面板、输入框 |
| `--light-text` | `#101828` | 标题、正文、关键数据 |
| `--light-muted` | `#667085` | 说明、辅助信息 |
| `--light-border` | `#e4ebf2` | 面板和控件边框 |
| `--light-accent` | `#009b8f` | 主操作、活动导航 |
| `--light-accent-ink` | `#04786f` | 青绿深色文字 |
| `--light-selected` | `#eaf9f6` | 选中、悬停背景 |
| `--light-disabled` | `#98a2b3` | 禁用文字 |

成功、警告、错误和信息状态分别保留绿色、琥珀色、红色和蓝色，不将所有状态染成青绿色。

### 7.3 覆盖范围

统一以下区域：

- 前台侧栏、顶栏、页面背景和导航状态。
- 工作台阶段条、场次列表、编辑区、预检区和底部流程条。
- 项目页、生成队列、资产页、积分页和设置页的主面板。
- 表格、弹窗、抽屉、输入框、下拉框、标签、禁用态和空状态。
- 现有低对比文本、白底白字和灰色按钮不可读问题。

面板使用清晰边框、低强度阴影和紧凑间距。普通面板圆角控制在 6-8px；不复制后台过大的营销式圆角。

## 8. 性能与风险

直接 4K 方案的主要风险是带宽和解码压力。五条文件合计约 97MB，且 `bicycle-smile` 接近 39Mbps。

控制措施：

- 仅当前背景和活动卡片播放。
- 仅下一条背景使用 `preload="auto"`。
- 非活动卡仅加载元数据。
- 页面不可见时暂停视频和同步循环。
- 使用海报避免等待期间空白。
- 记录媒体错误、降级档位和首帧等待时间。
- 保留环境变量快速切换到 2K/fast。

该方案是用户确认的第一轮验证方案，不承诺所有网络环境都能无等待播放。如果真实验证不合格，下一迭代切换到方案 2，而不继续增加并发预加载。

## 9. 验收标准

### 9.1 首页交互

- 收拢状态可同时辨认一张主卡和左右四张露边卡。
- 卡组位置比现状更靠左、更靠下，且不超出桌面安全区。
- 展开后五张卡均能通过真实鼠标坐标点击。
- 点击后 `aria-pressed`、背景源、活动卡视频三者一致。
- 连续快速点击不会出现旧请求覆盖新请求。
- 自动轮播后卡片顺序和背景保持一致。

### 9.2 媒体

- 线上 4K URL 返回 HTTP 200 并支持 Range 请求。
- 实际活动视频分辨率为 4K 档源文件。
- 非活动卡处于暂停状态。
- 主卡与背景正常播放时漂移不超过约 120ms。
- 4K 失败时可自动降级，页面不黑屏。
- 浏览器控制台无未处理媒体异常。

### 9.3 浅色主题

- 主要正文与背景满足 WCAG AA 对比度目标。
- 工作台、项目页、表格、弹窗和表单没有白底白字。
- 选中、悬停、禁用、成功、警告和错误状态可区分。
- 320px、390px、768px、1280px 和 1440px 无横向溢出或文字遮挡。

### 9.4 工程验证

- 前端类型检查通过。
- 生产构建通过。
- 相关自动化测试通过。
- 桌面和移动端真实浏览器截图通过视觉检查。
- 部署前创建源码和静态媒体备份。
- 部署后检查健康接口、静态资源哈希和五条 4K 文件响应头。

## 10. 发布与回退

1. 先在本地验证 4K、卡片命中和浅色主题。
2. 备份服务器源码、静态资源和当前构建产物。
3. 上传五条 4K 文件和前端代码。
4. 构建并部署 Web 静态资源。
5. 桌面端验证收拢、展开、点击、同步和连续切换。
6. 移动端验证无溢出和资源降级。
7. 若真实网络体验不合格，将 `VITE_CINE_MEDIA_TIER` 切换为 `2k` 并重新构建；后续实施方案 2。
