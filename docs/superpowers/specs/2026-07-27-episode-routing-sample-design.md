# 结构化分集、模型路由与示例项目设计

## 目标

让小说与剧本按真实内容结构决定可生产集数，简化模型路由，停用 ZML，把 Ripp 调整为 `gpt-image-2` 生图渠道，并让《北境婚书》通过正常创建流程进入项目工作台。

## 分集规则

- 小说优先识别明确章节标题，默认一章对应一集。约 2000 字只用于没有章节标题时的保守估算，不覆盖已有章节结构。
- 已有剧本优先识别“第 N 集”等集标题；没有集标题时，以场次边界估算可生产集数，字数仅作为最后兜底。
- 导入阶段展示检测依据、建议集数和最大集数。“想生成多少集”改成“本次生成范围”，选项为首集、前两集和全部；范围不能超过检测到的结构上限。
- 创建请求中的 `targetEpisodes` 表示本次生产的前 N 集，不表示把全部原文重切成 N 集。后端必须保留章节/集标题边界。

## 模型路由

- 删除没有实际行为差异的“自动推荐 / 自定义”切换。
- 文本、图像、视频三个通道直接使用统一的渠道/模型选择组件，清晰展示渠道名、模型名、用途和测试状态。
- ZML 渠道不再出现在新项目和管理端可选目录中。运行时代码保留旧 provider ID 的兼容读取，避免历史项目失效。
- 删除 Ripp 的 DeepSeek 文本配置；新增 Ripp 图像渠道，模型固定为 `gpt-image-2`。密钥只存本地忽略文件和服务器环境变量。

## 《北境婚书》导入

- 示例入口位于正常“新建漫剧”的内容输入步骤。
- 示例包以仓库内结构化清单提供 12 章/12 集剧本、角色、场景、道具及已有分镜元数据；不创建独立展示页。
- 点击示例后填充创建表单并标明 `12章 -> 12集`，随后仍经过创作设置、模型路由、创建任务和项目工作台。
- 资产图片只纳入项目真正使用的文件，并保留创作者可读名称与稳定 ID。

## 失败处理与兼容

- 无法识别结构时明确显示“按约 2000 字估算”，用户仍可在上限内选择生产范围。
- Ripp 测试区分 401/403、模型不存在、格式错误和成功返回图片数据。
- 旧项目中的 ZML 配置可继续解析，但不能新建或重新选择 ZML。
- 示例资源缺失时创建流程返回可读错误，不落半成品项目。

## 验证

- 单元测试覆盖 5 章小说得到 5 集、显式多集剧本按集标题识别、无标题文本兜底、范围上限限制和 ZML 隐藏。
- API 测试覆盖 Ripp 图像 provider 的模型、Base URL 和密钥映射。
- 前端类型检查与生产构建通过，并在桌面和移动宽度检查路由面板无重叠。
- 示例项目创建后核对 12 集、角色/场景/道具和剧本内容流转。
