# 项目安全审计与面试回答梳理

审计范围：当前仓库的前端 React/Vite、后端 Express/Prisma、PostgreSQL/Redis、Docker Compose、Nginx、环境变量模板与部署文档。未拿到云厂商安全组、SSH 配置、真实域名证书、线上日志、数据库备份策略，因此主机与云边界只做配置级建议。

## ① 安全风险总览

- 高危：5 个，其中已修复 4 个，待专项修复 1 个。
- 中危：7 个，其中已修复 5 个，待专项修复 2 个。
- 低危/业务体验 bug：4 个，其中已修复 1 个，待优化 3 个。
- 依赖漏洞：`pnpm audit --prod` 未发现已知漏洞。
- 编译状态：`pnpm -r typecheck` 已通过。

## ② 高危漏洞明细

### H1 默认管理员/演示账号与弱口令外露

- 风险描述：生产种子逻辑默认创建管理员与 demo 用户，后台登录页和部署文档展示默认口令，攻击者拿到地址后可直接尝试登录后台。
- 触发路径：`/admin` 登录页、`ensureSeedData()`、部署文档默认账号段。
- 攻击场景：公网部署后被搜索引擎或扫描器发现后台入口，使用默认账号进入后台，进一步管理用户、积分、模型渠道和 API Key。
- 修复状态：已修复。生产默认关闭 `SEED_DEFAULT_USERS`、`SEED_DEMO_USER`、`SEED_DEMO_DATA`；后台登录页不再展示默认口令；部署文档改为强口令管理员创建流程。
- 修复方案：生产环境必须通过一次性脚本创建管理员，密码不少于 12 位，并上线后轮换。

### H2 Mock 支付回调可被用于刷积分

- 风险描述：`/api/billing/mock-callback` 原先只要求登录，不限制生产环境，也不校验订单归属与金额一致性。
- 触发路径：登录用户创建订单后调用 mock 回调。
- 攻击场景：用户不经过真实支付流程，将待支付订单标记为已支付，获得积分。
- 修复状态：已修复。生产默认 `ENABLE_MOCK_PAYMENT=false`；mock 回调只能处理当前登录用户自己的订单，并校验渠道和金额。
- 修复模板：真实支付回调必须校验平台签名、订单金额、订单状态幂等、回调来源，并把 mock 入口仅保留在开发环境。

### H3 后台新建/重置用户允许弱密码

- 风险描述：后台新建用户表单默认填入弱口令，服务端只要求 6 位。
- 触发路径：后台用户管理创建用户、重置密码。
- 攻击场景：内部人员沿用默认密码创建账号，账号被撞库或猜测后进入系统。
- 修复状态：已修复。前端不再预填密码，服务端创建/重置后台用户要求至少 12 位。

### H4 分镜调度 SVG 直接 innerHTML 渲染存在存储型 XSS 风险

- 风险描述：前端曾直接用 `dangerouslySetInnerHTML` 渲染 `blockingSvg`。当前 SVG 由服务端生成，但一旦后续混入用户输入、AI 输出或被污染的持久化数据，可能形成存储型 XSS。
- 触发路径：项目工作台导演分镜预览的 `DirectorShotPreview`。
- 攻击场景：攻击者通过被污染的 SVG 字段插入事件属性、脚本标签或外链引用，用户打开分镜预览时触发脚本，进而窃取浏览器侧 Token 或执行后台操作。
- 修复状态：已修复。前端新增 SVG 白名单净化，只允许基础绘图标签和安全属性，移除 `on*` 事件、脚本协议、外链 `url()`、不受信标签和属性。
- 修复方案：对所有富文本、SVG、Markdown、HTML 预览统一做白名单净化；服务端生成 SVG 时继续对文本做 XML 转义；长期将登录态迁移到 `HttpOnly + Secure + SameSite` Cookie，降低 XSS 后果。

### H5 第三方模型 API Key 明文存储

- 风险描述：`ModelProvider.apiKey` 当前可写入数据库明文字段；一旦数据库泄露，模型供应商密钥会直接暴露。
- 触发路径：后台模型渠道配置 API Key。
- 攻击场景：数据库备份、日志、只读账号泄露后，攻击者拿密钥调用上游模型产生费用。
- 修复状态：待专项修复。
- 修复方案：使用 KMS/云密钥管理或 AES-GCM 信封加密；数据库只存密文和 key version；服务启动缺少主密钥时禁止写入 API Key；密钥展示只显示末 4 位；建立泄露后的轮换流程。

## ③ 中危风险明细

- 公开存储目录泄露：`/storage/exports`、`/storage/logs` 原可静态访问。已修复为默认只公开 `images,videos`，Nginx 阻断 exports/logs。
- 健康检查泄露依赖错误：`/api/system/health/dependencies` 原会返回数据库/Redis 错误细节。已修复为生产默认隐藏细节。
- 500 错误泄露内部异常：统一错误处理原会返回内部 message/detail。已修复为生产返回通用错误。
- 安全响应头缺失：Nginx 原缺少 CSP、nosniff、frame 防护等。已补充。
- 导出下载依赖原始存储地址：前端原用普通链接打开导出资源，容易诱导公开 exports。已改为带 Bearer 的 blob 下载。
- Token 存在 `localStorage`：一旦出现 XSS，会泄露长期 Bearer Token。建议改为 `HttpOnly + Secure + SameSite` Cookie，配合 CSRF Token 或双提交 Cookie。
- 内存限流不适合多实例：当前限流 Map 只在单进程生效。多实例部署应改为 Redis 滑动窗口限流，并对登录、兑换码、支付回调做独立阈值。

## ④ 低危业务 bug 明细

- 多处中文出现乱码：不影响入侵，但影响交付观感和面试讲解。建议统一 UTF-8，补一次文案修复。
- 图形验证码只在前端校验：只能提升交互门槛，不能作为安全边界。真正防爆破应依赖服务端限流、失败次数锁定、二次验证。
- 生产 Nginx 示例只监听 80：正式上线需要域名证书和 443，80 只做跳转。
- 最终 MP4 预览为了私有化 exports 已默认避开原始地址：下载可用；如要预览，建议增加受鉴权的临时签名预览地址。

## ⑤ 云服务器加固完整配置方案

- 安全组：只开放 `22/tcp`、`80/tcp`、`443/tcp`；PostgreSQL、Redis、Node API 只允许内网或本机访问。
- SSH：禁用 root 密码登录，使用密钥登录；开启 `PasswordAuthentication no`、`PermitRootLogin no`；限制登录用户。
- 防火墙：UFW 允许 OpenSSH、80、443，拒绝其他入站。
- Nginx/Caddy：强制 HTTPS；添加 HSTS；开启 CSP、nosniff、frame-ancestors；限制上传大小；隐藏 `.env`、隐藏文件、exports/logs。
- Docker：生产服务加 `no-new-privileges`；数据库、Redis 不映射公网端口；镜像定期升级并尽量 pin digest。
- 数据库：独立强密码；最小权限账号；每日自动备份；备份文件加密并限制保留周期。
- 密钥：`.env.production` 不进 Git；模型 Key 放云密钥管理或加密字段；离职/泄露后轮换。

## ⑥ 项目上线长期安全防护规范

- 自动化检测：CI 跑 `pnpm audit --prod`、typecheck、lint、secret scan、Dockerfile/Compose 扫描。
- 日志监控：记录登录失败、支付回调、积分调整、后台用户变更、模型 Key 更新；异常阈值告警。
- 权限管控：后台 RBAC 最小权限；财务、运营、客服分权；高危操作二次确认和审计日志。
- 数据防护：用户作品、导出包、音频、字幕默认私有；下载走鉴权接口或短期签名 URL。
- 安全发布：上线前检查生产 env、默认账号、mock 开关、CORS、TLS、备份、回滚方案。
- 应急流程：密钥泄露先禁用/轮换 Key，再查日志、封禁异常账号、补偿费用、复盘规则。

## 面试题回答模板

- 问：你在项目里怎么做安全？
  答：我按 OWASP 分层做，先看认证鉴权和业务闭环，再看输入校验、存储、部署和依赖。这个项目里我重点处理了默认后台口令、mock 支付刷积分、公开导出文件、错误信息泄露和生产安全头，并把开发便利开关和生产开关拆开。

- 问：怎么防越权？
  答：所有资源查询都带 `userId` 条件，后台接口再叠加 RBAC 权限。像支付回调这类高危业务，还要校验订单归属、金额、渠道、状态幂等，不能只靠前端隐藏按钮。

- 问：怎么防 SQL 注入？
  答：优先用 Prisma/ORM 参数化查询，禁止拼接 SQL；必须 raw SQL 时使用参数绑定和白名单字段，不把用户输入拼进表名、排序字段或 where 条件。

- 问：XSS 怎么防？
  答：React 默认转义文本，但要重点排查 `dangerouslySetInnerHTML`、富文本、SVG、外链图片。这个项目里我把分镜 SVG 预览改成白名单净化，只允许基础绘图标签和安全属性；防护上还要做输入清洗、输出编码、CSP、禁止内联脚本，并把 Token 从 localStorage 迁到 HttpOnly Cookie。

- 问：支付安全怎么做？
  答：真实支付回调必须验签、验金额、验订单状态、做幂等、记录原始回调摘要；mock 支付只能在开发环境开启，生产环境从路由和环境变量双重关闭。

- 问：云服务器怎么加固？
  答：公网只暴露 80/443/SSH，数据库和 Redis 不暴露；SSH 禁密码和 root；Nginx 强制 HTTPS、安全头、隐藏敏感目录；容器禁提权；密钥不进仓库，备份加密。
