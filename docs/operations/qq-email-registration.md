# QQ 邮箱注册与资源限制

注册流程：填写中国大陆手机号和 `qq.com` 邮箱 → 发送邮件验证码 → 验证邮箱 → 设置密码、同意协议 → 创建账号。手机号仅收集，不发送短信。现有账号继续使用原邮箱或手机号及密码登录。

服务器校验邮箱和手机号格式。邮箱验证码为随机六位数，10 分钟内有效，连续错误 5 次即作废。验证码校验成功后签发绑定邮箱、有效期 10 分钟、只能使用一次的注册凭证。修改邮箱、凭证过期或重复使用均不能注册。账号及积分账户在同一数据库事务中创建，事务失败可以在原凭证有效期内重试。

每个邮箱发送间隔至少 60 秒，每小时最多 5 次；每个来源 IP 每小时最多 20 次；全站每小时最多 200 次。Redis 中的记录全部设置过期时间。邮件或 Redis 失败会返回错误，只有邮件服务器实际接受发送请求才显示已发送；收件箱最终送达需用真实邮箱验收。

## 开通发信服务

在服务器的 `.env.production` 中设置以下环境变量。授权码仅保存在服务器，不能提交 Git、放入前端或写入验收报告。

```dotenv
REGISTRATION_SMTP_HOST=smtp.qq.com
REGISTRATION_SMTP_PORT=465
REGISTRATION_SMTP_SECURE=true
REGISTRATION_SMTP_USER=用于发信的QQ邮箱
REGISTRATION_SMTP_PASSWORD=该邮箱的SMTP授权码
```

SMTP 授权码在发信 QQ 邮箱的设置中启用 SMTP 后取得，区别于 QQ 登录密码。修改服务器配置后重新创建 API 容器，避免仅重启而沿用旧环境。生产 SMTP 强制验证 TLS 证书，不提供跳过邮件验证或返回明文验证码的调试开关。

公开 `GET /api/auth/registration-policy` 返回是否配置了发信服务。未配置时页面说明服务暂未开通，并暂停新账号注册。`mailAvailable: true` 只表示配置齐全，不代表真实邮件送达已经验收。

接口：

| 接口 | 用途 |
| --- | --- |
| `POST /api/auth/email/send` | 提交邮箱，发送验证码 |
| `POST /api/auth/email/verify` | 提交邮箱及验证码，获得临时注册凭证 |
| `POST /api/auth/register` | 提交手机号、QQ 邮箱、密码和临时凭证 |

隔离集成测试使用本地带证书的 SMTP 服务、测试 Redis 和测试 PostgreSQL；测试邮件不发给任何真实用户。生产验收还需使用指定 QQ 邮箱完成收码、验证和注册。

## 服务器资源

生产 Compose 为主要服务设置以下上限，重建后仍然生效：

| 服务 | 内存上限 | 内存加交换空间总上限 |
| --- | ---: | ---: |
| API | 1 GiB | 1.5 GiB |
| PostgreSQL | 512 MiB | 1 GiB |
| Redis | 256 MiB | 512 MiB |
| Nginx | 64 MiB | 128 MiB |
| 静态文件发布容器（一次性） | 128 MiB | 256 MiB |

API 的 V8 堆上限设为 512 MiB，为图片、视频处理及其他原生内存留出余量。Redis 数据上限为 128 MiB，并采用 `noeviction`，达到上限时报错以保留队列与验证记录。现有任务派发恢复机制会重试未完成的派发；用户验证操作会明确失败并允许重试。

此前审计记录约 3.7 GiB 总内存、2.5 GiB 可用内存，近 7 天未发现 OOM。已清理经过本机与服务器 SHA256 校验的旧备份，保留近期恢复点，并限制系统日志为 256 MiB、7 天。限制减少内存耗尽风险；仍需关注巡检中的可用内存、磁盘空间和队列写入失败。
