# 评测闭环迭代设计

日期：2026-11-08。范围：V2 评测证据与后台闭环实现。基线：`1f11cda`。实际测试与生产验收结果记录于 `outputs/evaluation-closed-loop-20261108/交付记录.md`。

## 本轮目标

让运营从具体结果出发，完成“收集问题 → 固定样本 → 受控评测 → 人工复核 → 比较改动 → 附证据关闭问题”。维持前台暖白与青绿、后台现有管理结构。评测默认不触发真实生成，不自动更换生产提示词或模型，不通过规则分宣布作品可商用。

依据与现状分析见 `outputs/evaluation-closed-loop-20261108/方案研究.md`。

## 必须修正的现有问题

1. 样本集只存项目 ID，运行读取可变项目内容。
2. 图片、视频规则用资产数量生成构图、畸形、自然运动等伪视觉分数。
3. LLM 只收文本却被要求判断未见媒体；用户反馈默认进入模型上下文，影响独立校准。
4. 合法 0 分被 `||` 覆盖；无效响应退回规则值；全失败用量可能丢失；没有强制单次模型提交。
5. 对比运行混合规则、模型与融合报告，并比较不同样本总体平均。
6. 反馈沉淀为前端两次写入，缺少复测绑定；沉淀被当成处理完成。
7. 运行没有样本级证据、人工评审和持续可查询的执行状态。

## 数据契约

兼容历史记录，采用增量字段与新表，不回填虚构快照。历史无证据记录显示“旧版记录，证据不足”，不能自动进入可信对比。

### 固定样本

新增样本记录，绑定样本集、项目、阶段和稳定样本键，保存白名单字段构成的快照及 SHA-256。快照包括评分所需文本、镜头与角色字段、资产 ID/状态/来源指纹、实际生成提示词版本摘要；不保存用户邮箱、密钥、认证信息或任务请求中的任意私密字段。

保存样本集时事务捕获样本；运行样本集时读取已保存快照。直接选择项目时也先捕获快照再运行。旧样本集在首次显式运行时生成本次快照并提示历史局限。新增修复版本应保存为新样本集，保留原样本。

文本和元数据完整保存或因上限明确拒绝，不能静默裁切后宣称全量评测。发送模型的文本可有明确采样上限，快照记录实际发送内容与覆盖范围。媒体以实际资产身份和来源指纹绑定；无法验证媒体时显示缺口。

实施补充：本地媒体增加文件内容 SHA-256，并在展示、提交复核时重新校验，拒绝同地址内容被替换。单文件 128 MiB、每样本 512 MiB 核验上限；外链、文件缺失或超限均明确保留“内容无法核验”，不计为已查看原样本。历史媒体版本不混入当前版本复核。新版固定样本、运行和复核证据保留，后台删除仅继续支持非执行中的旧版记录。

### 评测尝试

新增样本级尝试记录，关联运行、项目与阶段。执行前写入样本快照、评测器类型/渠道/模型、实际评分模板、指纹与状态。提交标记必须在供应商调用之前持久化。结果包括报告、错误、是否已提交、耗时、使用量与成本证据。

新运行添加请求幂等键及协议版本。重复同键同参数返回原运行，异参冲突；不能再次收费调用。网页超时后通过请求键或运行 ID 查询已有记录。每次调用 `singleSubmission: true`，禁用模型及端点自动回退。供应商结果未知时停止剩余自动调用，进入待核对状态。

执行中断后的运行保留尝试，可显示为待核对；禁止把已提交尝试重新执行。运行汇总由持久化尝试重算，即使全部模型失败仍保留调用及 usage。管理员删除运行需拒绝正在执行或结果未知的记录，避免抹掉核对证据。

人工核对入口要求供应商终态、调用/账单依据和处理说明。登记具有幂等与状态冲突保护，保留原始状态和错误，终止待核对状态但不补造评分或 usage，也不自动重发。缺失报告明确保留；成本未知仍需账单核验。

### 证据分层

- 结构检查：只检查字段、镜头编号、关联资产、任务状态、文件覆盖等可观察事实。
- 文本评审：剧本、角色文字设定与分镜文本；不宣称看过图片或视频。
- 媒体复核：人员确实查看具体媒体后记录；不能被文本分或资产数量替代。
- 作者认可：来自作者确认流程，保留原有语义，不由管理员或评测模型替代。

模型响应必须结构校验，接受 0，拒绝非数值、越界、缺维度、非数组的问题列表等；通过状态由受控阈值或关键失败条件决定，不盲信模型 `pass`。评分模板视为版本化评测契约。不同证据通道分别汇总，不再给未校准的规则 35% / 模型 65% 混合值制造确定性。

### 成本

保留现有调用次数上限，限制输出 token，并在可核对的精确渠道/模型价格基础上记录预算。配置估算与实际 usage 推导成本分开；无价格或无 usage 显示未知，不能显示免费。不向作者积分账户扣除后台评测费用。成本记录保留计价规则快照，账单核对独立完成。

供应商响应中的模型名称另行记录；返回模型与所选评测器不一致时，不形成可比较评分，也不借用所选模型价格。无有效 usage 的响应只保留身份及回执信息，成本保持未知。

### 人工复核

新增追加式复核记录，绑定具体尝试及样本指纹，保存复核者、结论（可用／不可用／证据不足）、理由、时间与请求幂等键。更改意见保留历史；并发编辑检查版本，避免覆盖。

界面先展示输入、结果与适用证据，再呈现或展开自动评分，降低分数锚定。复核图片和视频时提供实际媒体；来源发生变化时禁止把新媒体当成旧样本。

无需配置付费文本模型，也可在结构检查尝试上人工复核完整剧本或分镜文本，并用匹配复核闭环反馈。人工文本意见不会用于校准结构检查；自动文本抽样不完整时也不进入完整人工意见的一致率。

校准显示有人工意见的样本数量、自动判断一致数和分歧数。只比较同一证据范围；用户反馈的粗粒度满意度不能自动当成标准标签。

快照捕获使用可重复读事务，跨多表读取不混入并发修改。仅对已回滚的准备事务处理序列化/唯一性竞争，重试范围不包含供应商调用。CSV/Excel 从固定样本导出作品名称、问题与复核记录，不再查询当前项目或当前用户反馈替换历史证据。旧版假视觉分、融合分与未配对均分比较等不可达实现已移除。

### 实验对比

按阶段与样本键配对，列出新增、缺失和证据变化，不用未匹配样本推动胜负。每个样本每个通道只计算一次，规则/模型/人工不混算。

必须检查样本指纹、阶段、采样上限、反馈使用设置、实际评分模板和评测模型。若改变的是评测器，“给分更高”只代表评分差异，不能表示生产质量提升；此类准确度判断需要人工标注的校准证据。

生产效果对比只有在相同输入、固定评测器和可追溯生成版本下才可称为改进证据。当前只靠手选生成模板名称的记录作为声明标签，不得冒充实际生成来源。条件不足时保存描述性对比并输出“待验证”，不自动发布或切换生产版本。

结论同时考虑平均分、通过率和逐样本回退，避免均分上升掩盖关键样本失败。样本量和覆盖缺口在 UI 展示，不声称统计显著性。

### 反馈闭环

反馈转样本改为后台单事务操作，重复请求不生成重复数据集。原始反馈保留，沉淀样本不代表修复。

解决质量问题时要求处理理由及关联的复测/人工证据；校验其项目、阶段与时间。允许“关闭且说明原因”与“完成修复并有证据”两个不同结果。反馈页可直达样本和复测记录，记录详情可返回问题。

## 后台体验

沿用“创作质量中心 → 评测实验”入口，不新增平行孤岛。运行表增加查看证据；详情展示样本覆盖、通道结果、调用状态、成本记录、评分依据和复核记录。失败、空数据、历史记录、预算不足和写入结果未知分别有文案与操作。

实验表显示“可比／缺证据”和逐样本差异，“pending”不能显示为“持平”。运行默认选择较小范围；模型评分默认不纳入用户反馈。图片/视频不可用的自动评测能力直接说明，引导媒体复核。

前台评测抽屉显示评分依据及局限，避免把结构检查通过显示成媒体质量验收。

## 验收标准

隔离 PostgreSQL 测试验证：项目更新不改变固定样本；同键并发仅一次执行；异参拒绝；0 分保留；无效返回不回填规则分；失败 usage 保留；返回模型不匹配时不套价或形成可比较分数；未知结果不重发；跨样本或跨评测器不误判胜负；复核冲突与幂等；反馈沉淀原子性；解决状态必须有匹配证据；非管理员无访问权。

浏览器验证桌面、手机、深浅主题、空数据、历史记录、加载与失败、运行后查询、证据详情、人工复核、比较结论与反馈闭环。UI 夹具和数据库事实分别记录。

全量项目检查通过后按持续授权发布：新提交、PR、合并、main CI、容量预检、腾讯云部署、GitHub/服务器/deployed/readiness 版本一致、数据库保全、公开页面浏览器冒烟与干净工作区。

真实媒体质量、真实 usage/账单、作者认可、邮件投递和现金收款保留各自验收边界。
