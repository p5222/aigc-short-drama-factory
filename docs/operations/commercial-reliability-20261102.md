# 商用可靠性迭代与异常处置

本轮重点是任务执行、购买恢复、账户安全与后台处置四条闭环。接口配置仍使用[后台配置手册](platform-configuration.md)；本说明记录异常情况下的实际行为，不把协议测试当作真实生成质量或真实收款验收。

## 1. 供应商结果未知时停止重复提交

剧本、内容创作、文字分镜在发出请求前持久化一次提交记录。文字请求与响应正文读取使用统一超时。明确未提交、明确被拒绝与结果未知分别记录。

- 超时、断线、无法解析成功响应、发送后进程退出等情况保留待核对状态；不会因队列重试或租约过期自动再次付费。
- 未交付部分的冻结积分保留。用户任务中心显示核对提示并可进入工单；直接重试、取消不能绕过未知状态。
- 有明确未提交或拒绝证据的失败可重试，继续使用原任务的输入、模型与报价约束。
- 管理员结束后，晚到结果不能覆盖任务或重新结算。旧版运行中任务没有提交证据时保守处理。

文字供应商没有可查询任务编号时，平台无法凭空确认上游费用。必须核对供应商调用记录和账单；平台释放未交付冻结积分不代表供应商已退款。

## 2. 后台异常任务处置

入口：后台 → 异常任务。

1. 选择生成任务或导出任务，按平台任务编号、用户编号或项目编号搜索。默认关注超过两分钟没有新进度的待处理任务；需要查历史时切换全部任务。
2. 打开详情，核对提交尝试、渠道模型、已知上游任务编号、源版本指纹和本任务冻结积分。详情不输出 API Key、完整提示词或请求内容。
3. 视频存在上游任务编号时，“查询原任务”只查询该编号，不重新生成，也不会据此直接扣款或伪造交付成功。
4. 对照供应商记录填写核对理由，确认结束未交付任务。活跃心跳、状态已变化、已完成任务均阻止不合适的处置。
5. 状态冲突时刷新详情并重新确认；网络响应丢失时保留原请求身份重试。同一处置不会重复释放积分，记录可在详情与审计中回查。

内容创作的父操作和未交付子任务一起结束；已完成子任务及其已消耗积分保留。导出保留已生成的配音、素材与历史结果，可在核对后发起新导出。

## 3. 购买恢复与金额确认

前台发送购买请求前，先按账号和商品保存请求身份及已确认的价格、积分、会员权益。浏览器拒绝存储或存储损坏时暂停新购买，原订单仍可查询。

同一账号、同一商品存在未结清微信订单时，不同标签页、不同请求编号都会关联到同一原订单。所有别名持久化；即使原订单之后支付成功或关闭，重放旧请求也不会生成新单。二维码过期但尚未确认关闭的订单同样先核对。

后台暂停收款、停用套餐或改价不会改变旧订单已保存的金额和权益。已有二维码及终结订单可直接读取；缺少二维码时可以查询原上游订单，但暂停状态不会创建新上游付款。新购买发现价格或权益变化，会明确拒绝创建，刷新后重新确认。

会员仍按月手动续费，仅同档续费，不自动扣款。商业会员身份不授予后台权限。

## 4. 验证邮箱、换绑和找回密码

新注册在邮箱验证成功后写入验证时间。旧账号、后台新建账号不自动获得“已验证”标记。

- **老账号验证/换绑**：登录 → 我的账户 → 验证邮箱，填写当前或新的 QQ 邮箱、当前密码，收取验证码后保存。成功后撤销全部登录会话，使用新邮箱或原手机号重新登录。
- **忘记密码**：登录弹窗 → 忘记密码，填写已验证的 QQ 邮箱、验证码与新密码。仅启用中的普通创作者账号适用；管理员与未验证邮箱账号使用受控人工恢复。
- **登录后改密**：需要当前密码，新密码为 8–72 个字符。成功后当前会话也失效。
- **管理员修改邮箱**：真实改变邮箱会清除原验证标记；仅改昵称或原邮箱不变不会误清。修改身份、状态、联系方式或重置密码会使旧安全验证失效。

注册、换绑、找回使用相互隔离的 Redis 验证记录，验证码与临时凭证不能串用。安全验证绑定发送时的用户、邮箱、密码状态与递增安全版本；停用再启用、换走再换回、改密码后，旧验证码和旧凭证不能复活。

验证码有效期 10 分钟、发送间隔 60 秒，连续 5 次错误作废。每种用途继续执行邮箱/IP/全站小时上限。公开找回请求对不存在、未验证、停用和管理员账号采用一致发送结果；收到安全邮件本身不证明账号有恢复资格。邮件或 Redis 故障明确失败。

数据库更新与全部会话撤销在同一事务内执行。失败恢复临时凭证时不延长原有效期；提交已发生但响应不确定时，旧安全版本也不能覆盖新状态。密码、验证码和恢复凭证不写入后台审计。

接口：

| 接口 | 身份与用途 |
| --- | --- |
| `POST /api/auth/email-binding/send` | 登录用户、当前密码，向目标 QQ 邮箱发码 |
| `POST /api/auth/email-binding/verify` | 登录用户、当前密码、验证码，取得换绑凭证 |
| `PATCH /api/auth/profile` | 邮箱变更必须携带换绑凭证；与普通资料单独保存 |
| `POST /api/auth/recovery/send` | QQ 邮箱，统一安全邮件与速率限制 |
| `POST /api/auth/recovery/verify` | 已验证 QQ 邮箱和验证码，取得恢复凭证 |
| `POST /api/auth/recovery/reset` | 恢复凭证与新密码；不自动登录 |
| `POST /api/auth/password` | 登录用户与当前密码；撤销全部会话 |

发信复用后台“邮件通知”设置或受保护的服务器环境变量，不需要为找回再接一套邮箱服务。

## 5. 发布与验收边界

增量结构为 `GenerationTask.execution`、`User.emailVerifiedAt/authVersion`、`TaskResolution` 与 `CheckoutRequest`。旧数据保留，邮箱验证时间不回填；旧订单按原唯一请求编号兼容恢复并补齐别名。

回归包括真实隔离 PostgreSQL/Redis、带证书的本地 SMTP、HTTP 权限与会话、桌面/手机故障交互、生产镜像和恢复检查。发布后核对 GitHub main、服务器 main、部署 revision 与公开 readiness，检查原表记录数量、新表、前端文件、备份、Redis AOF 与 FFmpeg。

仍需独立验收：实际供应商连续样片、作者认可、真实 usage 与供应商账单对应、真实微信支付收款和结算、真实邮箱送达及受众效果。配置齐全或测试通过均不能代替这些业务证据。
