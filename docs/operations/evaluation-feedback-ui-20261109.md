# 评测与反馈交互契约

本轮沿用[评测证据契约](evaluation-closed-loop-20261108.md)，只调整前端工作流和样式。

## 创作者

「评测与反馈」分为质量建议和我的反馈。建议展示分数及其检查范围、完整问题和调整建议；反馈展示作者评分、可用性、当前状态和处理记录。零分直接展示，不作为缺失值处理。两类记录均按提交时间倒序，可按阶段筛选，每次展示八条。

资产评价使用统一表单。评分和可用性没有默认值；标签多选，说明最多 2000 字。提交时锁定输入和按钮，失败保留内容。成功保存后即清空本次输入，后续刷新失败单独提示，不把已完成写入呈现为提交失败。表单以资产身份为 key，防止上一资产的意见跟随选择进入另一资产。

## 运营

评测创建按样本、范围与方式组织；高级版本和样本保存默认收起。运行按钮旁显示作品、阶段、调用上限和预算。结构检查不调用付费模型；原有请求身份、待核对状态和证据范围规则继续生效。

反馈工作台采用队列和详情。详情的「处理记录」与「样本与复测」可相互切换，切换不清空草稿。手机默认显示队列，进入详情及返回列表时移动焦点。已收到、已归因、已建样本和复测解决分别来自已保存数据；不能由编辑中的草稿提前推进。

筛选输入只有点击查询后才应用。分页继续使用已应用条件，包括回到第一页；优先级和可用性只筛选当前数据库页，界面明确该范围。离开草稿的查询、切换和导航需要确认；取消保留草稿。确认刷新期间禁用编辑，避免新输入被异步响应覆盖。写入期间阻止查询、分页和重复提交。

复核首先展示固定原始样本，再填写独立意见，自动评分按需展开。关闭、刷新、换样本或关联已有复核前保护未保存内容；复核写入和刷新期间锁定相关操作。媒体不可核验时不能提交可用结论。保存反馈后，详情、队列和统计使用接口返回的规范记录。

## 视觉与验证

前台使用设计系统语义色；后台使用 `--adm-*` 语义色，保持暖白青绿与石墨灰深色。布局在桌面使用并列阅读和编辑区域，窄屏顺序排列，保留键盘焦点、错误、加载和空状态。

浏览器用例覆盖深浅主题、桌面手机、完整建议、零分、筛选分页、草稿确认、重复提交、状态同步和证据闭环。夹具只能验证这些交互，不能作为真实供应商质量、账单、作者认可或收费验收。
