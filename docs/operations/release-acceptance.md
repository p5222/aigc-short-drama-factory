## 发布基础设施

1. 确认新版 hook 已安装且语法检查通过，发布用户有依赖工具、目录权限和足够磁盘空间。保留旧镜像与上一次可用备份。
2. 发布日志确认先取得锁，再完成数据库、素材与源码备份校验；备份有 `COMPLETE` 和 `SHA256SUMS`。日志中没有备份成功之前修改源码的记录。
3. 数据库 schema 同步只运行在发布步骤，普通 API 容器重启不会安装依赖或修改 schema。发布没有破坏性同步参数。
4. `deployed`、GitHub SHA 和公网 `/ready` revision 一致，响应是 JSON，`ok` 为 true；数据库、Redis 和任务执行器就绪。SPA HTML 200、仅 `/health` 正常均不通过。
5. 浏览器加载新的前端资源，没有资源 404；已打开的旧页面能继续获取原来的带 hash 静态资源。私有媒体通过 API 鉴权。
6. 仅在隔离或预发布环境执行依赖中断/重启演练：依赖不可用时 `/ready` 失败，恢复后重新就绪；API 重启后遗留任务按设计恢复，不重复扣费或创建结果。

| 项目与内容 | 创建项目、录入剧本、角色/分镜处理、保存、刷新和重新打开后数据一致；缺少必要输入有可操作提示。 |

| 积分 | 提交、成功、失败、取消和重复请求的余额与账本一致；并发不足余额时没有透支；错误不会留下永久冻结额度。 |
