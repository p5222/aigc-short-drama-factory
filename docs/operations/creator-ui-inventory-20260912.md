## 本轮应处理的确定缺口

### F1 — 内容创作的草稿生命周期不完整（P1）

- `ContentWorkspace.tsx:571–593`：`OutlineStage` 的 `outlineDraft` 仅存组件，点击顶部“结构拆解”使该分支卸载；再次回“大纲确认”从后端原始大纲初始化。未保存改动直接消失，无确认/草稿恢复。
- `ContentWorkspace.tsx:459–481,546–557`：编辑第1章时点第2章目录，`editingChapter`仍是第1章；第2章显示正常正文，但底部由 `editingChapter ? null : ...` 隐藏所有动作，保存/取消也因chapterNo不匹配而不可见。用户只能自行发现回到原章恢复编辑器。
- `ContentWorkspace.tsx:373,410–416`：返回作品直接回调；素材标题/正文、章节、大纲均未监听 `BEFORE_CREATOR_NAVIGATION/beforeunload`。来源及章节的失败保留只覆盖当前挂载，不覆盖离页。
- 最小设计修复：内容项目级draft owner，按项目/草稿种类/章节key隔离；顶部固定“未保存/保存中/已保存/待刷新”；切章、切阶段、离页共用同一guard，明确“继续编辑/放弃”；保存成功与读取失败分开。复用已成功的 ContentStage/ShotDraft 模式，不复制整个生产台布局。

### F2 — 内容入口和加载状态可能与当前 URL 不一致（P1）

- `App.tsx:425` 未对 ContentCreatorPage 加 contentId 的key；`ContentWorkspace.tsx:65–99` 初始化选择后用 `current || initialSelectedId`，`content/model.ts:16` 会保留仍存在的current。A内容页中用Shell搜索打开B时，URL可变为B，但页面仍是A；`__new__`的 `creating/startBlank`同样只在初始化时决定。
- `ContentWorkspace.tsx:102–124,429–435`：package请求中没有独立加载状态。读取现有项目时短暂先呈现“结构拆解未完成/用标题重新拆解”，失败后仍保留这些无数据推导的操作。
- 最小修复：内容ID作为页面实例/请求归属；真实loading/error/not-found分开，取得package后才导出阶段；切换前先经过F1草稿保护。无效ID不能静默显示第一条作品。验收不需要调用任何生成接口。

### F3 — 项目刷新错误已写入 state，但当前可见树没有渲染（P1）

- `ProjectWorkbenchPage.tsx:145–159,264–284` 在导出版本核验/顶栏刷新失败时写入父级 `error`。
