# 后台管理 V2 模块重构记录

更新日期：2026-07-04

## 本轮目标

这次不再只优化后台左侧全局侧边栏，而是把主要后台模块都升级成成熟管理后台的工作台结构。参考 Sub2API 的后台信息架构，核心原则是：左侧负责模块内分层，顶部负责搜索、筛选和主操作，内容区负责真实数据表格、批次管理、行内编辑和弹窗创建。

## 已落地模块

### 用户管理

- 新增模块内侧栏：全部用户、创作者、后台成员、已付费、正常、停用、未设密码。
- 新增顶部 KPI：用户总数、积分余额、付费用户、后台成员。
- 新建用户从页面长表单改为弹窗。
- 账号列表支持搜索、角色筛选、状态筛选和可见行批量启用/停用。
- 保留真实业务操作：修改姓名、角色、状态、重置密码、积分调整。

### 兑换码

- 新增模块内侧栏：未使用、全部、已使用、可用、未开始、已过期、已停用、已用完。
- 新增明细视图和批次视图切换。
- 生成兑换码从页面长条改为弹窗。
- 明细视图可定位单个兑换码；批次视图保留批量启用、停用、删除未使用。

### 套餐会员

- 新增模块内侧栏：全部套餐、前台展示、已停用、低价体验、高额套餐。
- 新增顶部 KPI：套餐数量、平均售价、积分总额、有赠送。
- 新增套餐从长条表单改为弹窗。
- 保留表格内编辑售价、积分、赠送、标签、卖点、店铺链接和状态。

### 订阅会员

- 新增模块内侧栏：全部会员、前台展示、已停用、模型折扣、优先队列。
- 新增顶部 KPI：会员方案、月费合计、月额度、最高队列。
- 新增会员从长条表单改为弹窗。
- 保留月费、月额度、折扣、队列、权益、店铺链接和状态编辑。

### 模型路由

- 新增模块内侧栏：全部渠道、文本、生图、视频、配音、向量、缺 Key、启用中、停用、自动路由、手动固定。
- 新增顶部 KPI：渠道总数、视觉渠道、已配置 Key、自动路由。
- 新增模型渠道从长条表单改为弹窗。
- 保留开源 Agent/视觉插件状态、网关策略预览、模型测试、API Key 写入、模型池、额度池和路由模式配置。

### 价格策略

- 新增模块内侧栏：全部价格、文本、生图、视频、配音、向量、前台生效、停用、高成本、高积分、无渠道关联。
- 新增价格策略从长条表单改为弹窗。
- 保留按供应商分组、模型类型标签、积分单价、供应商成本、启停和删除操作。
- 新增高成本/高积分/无渠道关联视角，方便后续做毛利控制和策略清理。

## 通用后台规范

- 所有核心模块使用 `AdminModuleWorkbench`：左侧模块内侧栏 + 右侧业务主区。
- 低频新增操作使用 `AdminModal`，避免长表单长期占据列表空间。
- 搜索、筛选、批量操作、创建按钮统一放在 `AdminToolbar`。
- 重复数据用表格或分组卡片承载，状态用轻量标签表达。
- 页面保留真实 API 和真实数据行为，本轮主要重构 UI 与管理逻辑，不改数据库结构。

## 产品意义

后台从“能操作”升级为“能运营”：管理员可以先按业务问题分层定位，再用搜索筛选精确处理数据，减少误操作和查找成本。对云部署后的真实用户运营来说，这套结构更适合长期维护、客服处理、成本控制、商业化配置和模型生产调度。

## 面试表达

这个模块可以这样介绍：我参考 Sub2API 的成熟后台信息架构，对项目后台做了 V2 产品化重构。重点不是单纯美化，而是把用户、兑换码、套餐、会员、模型路由、价格策略都抽象成统一工作台：模块内侧栏负责业务分层，顶部工具栏负责检索和操作，主内容区负责真实数据管理，低频新增动作统一弹窗化。这样既提升了后台专业度，也让运营、商业化和模型成本控制形成清晰闭环。
