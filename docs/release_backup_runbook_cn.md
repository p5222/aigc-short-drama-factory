# 发布、备份、清理数据说明

更新时间：2026-07-04

## GitHub 是否更方便？

是，更方便。

GitHub 的作用不是“替代服务器”，而是管理代码版本：

- 每次改动都有记录。
- 可以知道线上是哪一版。
- 出问题可以回滚到上一版。
- 后续可以做自动发布。
- 多人协作更清晰。

服务器仍然负责真正运行网站、数据库和文件。

## 数据库备份在哪里？

当前方案：备份在服务器里。

默认目录：

```bash
/opt/manjiao-backups/时间戳/
```

里面会有：

- `aigc_drama.dump`：PostgreSQL 数据库备份
- `storage.tar.gz`：生成的图片、视频、音频、导出文件
- `compose-ps.txt`：当时容器状态
- `RESTORE.md`：恢复说明

## 备份原理

数据库不是一个普通 Excel 文件，不能直接复制数据库目录。

PostgreSQL 推荐用 `pg_dump` 导出：

- 它会把数据库里的表、用户、项目、任务、积分、模型配置等导出成一个备份文件。
- 恢复时用 `pg_restore` 导回数据库。

`storage` 是普通文件：

- 图片
- 视频
- 音频
- 字幕
- 导出文件

这些用 `tar.gz` 打包即可。

## 为什么发布前必须备份？

因为发布可能包含：

- 代码变更
- 数据库结构变更
- 清理数据
- 重启服务

如果发布失败，有备份就能退回。
