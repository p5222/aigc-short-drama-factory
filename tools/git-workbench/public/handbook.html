PORTABLE / MANUAL V1.1
FROM ONE COMPUTER TO THE NEXT

换一台电脑，继续你的项目。

按步骤完成一次接入，之后沿用同一套开发、提交、推送和发布流程。

先分清两种权限

GitHub 登录决定你能否拉取和推送代码；服务器 SSH 公钥决定这台设备能否发布服务器。仅开发代码，不需要服务器权限。

本手册可在工具左侧打开。尚未启动工具时，直接双击便携包内 public/handbook.html 也能离线查看；在浏览器按 Ctrl+P（Mac：⌘P）可打印或保存为 PDF。

01 / BEFORE YOU LEAVE

在旧电脑上，把进展推到 GitHub

  1. 在编辑器保存代码，并完成必要测试。
  2. 打开工作台，点击刷新状态，逐个查看文件差异，勾选本次需要的文件。
  3. 填写提交说明，点击提交选中文件，再点推送当前分支。
  4. 在 GitHub 确认分支与最新提交已经出现，记下仓库地址、分支名和提交号。

提交只保存在当前电脑；推送后，新电脑才能拉取。如果需求还没做完，可以留在功能分支，暂不合并 main，下一台电脑继续这条分支。

内容如何转移
代码、提交、分支、项目文档推送 GitHub，再在新电脑克隆 / 拉取。
工作台工具下载最新便携 ZIP，或复制整个 git-workbench 文件夹。
开发环境 .env 与模型 Key使用受控的安全渠道单独配置；不要提交 GitHub。
数据库、用户上传素材、生成结果不随代码同步。开发通常使用本地测试数据；需要迁移时单独备份恢复。
SSH 私钥留在原设备；新设备生成自己的密钥并授权公钥。
02 / SET UP ONCE

新电脑安装环境，并登录 GitHub

先安装 Git、Node.js 24、GitHub CLI。安装后重新打开终端：Windows 用 PowerShell；macOS 用“终端”；Linux 用终端。

git --version
node --version
gh --version

上面三条都能显示版本后，执行：

gh auth login
gh auth setup-git
gh auth status

登录时选择 GitHub.com → HTTPS → 通过浏览器登录，按终端显示的设备码完成网页授权。使用有仓库权限的账号；你的项目是私有仓库，其他账号需先获得协作者权限。

配置提交身份，把示例文字换成自己的名字和 GitHub 提交邮箱：

git config --global user.name "你的名字"
git config --global user.email "你的GitHub提交邮箱"

可在 GitHub 账号 Settings → Emails 查看邮箱或隐私提交邮箱。这里配置的是提交署名，不是密码。

03 / OPEN YOUR WORKSPACE

启动工具，克隆或打开项目

  1. 从 GitHub Releases 下载便携 ZIP，完整解压。私有仓库需要先登录。
  2. Windows：双击 start-windows.bat。macOS / Linux：在解压目录运行 sh start-unix.sh。
  3. 浏览器打开 http://127.0.0.1:4318/。启动窗口保持运行；关闭窗口或按 Ctrl+C 会停止工具。

工具不依赖 Codex；在普通浏览器中就能用。此地址代表当前电脑，不能用它访问另一台电脑的工具。

第一次拿到项目：克隆

在“GitHub 仓库地址”填入：

https://github.com/p5222/aigc-short-drama-factory.git

在“本机项目文件夹 / 克隆后的新文件夹”填入一个尚不存在的新文件夹绝对路径，父目录需要已存在：

系统示例
WindowsE:\Projects\aigc-short-drama-factory
macOS/Users/你的用户名/Projects/aigc-short-drama-factory
Linux/home/你的用户名/Projects/aigc-short-drama-factory

点击克隆项目，等待“操作记录”显示完成。页面会自动连接新项目并显示当前分支。仓库历史或素材较多时，首次克隆可能较慢。

这台电脑已经有项目：打开

填入已有 Git 项目目录，点击打开项目。不需要重复克隆。重启工具后可以再次打开该目录；工具不保存账户凭据或最近目录。

04 / YOUR DAILY LOOP

日常迭代：每项需求用一条功能分支

  1. 工作区干净时，在分支下拉框选择 main，点击切换。
  2. 点击拉取当前分支，获取最新 main。
  3. 输入新分支名，例如 codex/login-improvement，点击新建分支。
  4. 在 VS Code、Codex 或其他编辑器中修改代码并测试。工作台用于管理 Git，不是代码编辑器。
  5. 返回工具点刷新状态，点击文件名查看差异，逐项勾选需要提交的文件。
  6. 填写提交说明，例如 feat: 增加角色资产筛选，点击提交选中文件。
  7. 点击推送当前分支，再打开PR / 合并页面，在 GitHub 审查并合并到 main。
  8. 合并后回到 main，再拉取最新代码，开始下一项需求或发布。

工具不直接提交或推送 main / master；这样功能改动可以在 PR 中检查。团队可由同事审查；个人开发也可以自查并记录结果。

接续另一台电脑上尚未合并的分支

在新电脑的项目目录打开终端，将下面分支名替换成旧电脑已推送的分支：

git fetch origin
git switch --track origin/codex/login-improvement

如果本地已经有这条分支，则执行：

git switch codex/login-improvement
git pull --ff-only origin codex/login-improvement

再刷新工作台即可。V1.1 下拉框只列本地分支，所以首次接续远端分支需要上面的终端步骤。

按钮分别做什么？

操作结果
刷新状态重新读取本地分支、文件和同步状态。
刷新远端获取 GitHub 最新提交信息；不修改工作文件。
拉取当前分支更新当前分支文件。存在未提交文件或历史分叉时会停止。
提交保存选中文件的本地版本；没有上传。
推送把当前功能分支的提交上传到 GitHub。
PR 合并在 GitHub 把功能分支并入 main；不会自动更新生产服务。

新建分支以当前提交为起点。已有暂存内容、冲突或未提交文件时，请先在编辑器处理；不要为了切换分支随意删除个人草稿。工具不会自动丢弃文件。

05 / RUN THE PROJECT

需要在新电脑运行漫角项目时

仅拉取 / 推送代码不需要启动数据库。要运行完整项目，再安装 Docker 和项目指定的 pnpm。在项目根目录执行：

npm install -g pnpm@11.7.0
pnpm install --frozen-lockfile

复制配置模板为本地配置。Windows PowerShell：

Copy-Item .env.example .env

macOS / Linux：

cp .env.example .env

只在配置文件尚不存在时复制，已有配置不要覆盖。填入开发所需环境变量，再运行：

docker compose up -d postgres redis
pnpm --filter @aifilm/shared build
pnpm --filter @aifilm/api db:generate
pnpm --filter @aifilm/api db:push
pnpm dev

db:push 这里针对本地开发数据库；不要把开发配置指向生产数据库。前端地址 http://localhost:5173，API 健康检查 http://localhost:4000/health。

完成修改后按项目要求验证：

pnpm test
pnpm typecheck
pnpm build
06 / AUTHORIZE THIS DEVICE

只有需要发布服务器的电脑，才配置 SSH

服务器：43.139.101.102；用户：ubuntu；服务器 Git：/opt/git/aigc-short-drama-factory.git。GitHub 登录不会自动获得服务器权限。

第一步：新设备生成自己的密钥

Windows PowerShell：

$keyDir = Join-Path $env:USERPROFILE '.ssh'
New-Item -ItemType Directory -Force $keyDir
ssh-keygen -t ed25519 -f (Join-Path $keyDir 'manjiao_git') -C manjiao-new-device

macOS / Linux：

mkdir -p ~/.ssh
ssh-keygen -t ed25519 -f ~/.ssh/manjiao_git -C manjiao-new-device

按提示设置密钥口令。如果同名密钥已经存在，不要覆盖，先确认是否可以继续使用。manjiao_git.pub 是可交给管理员的公钥；manjiao_git 是留在新电脑的私钥。

第二步：在已有管理员权限的电脑上授权公钥

将新设备的 .pub 文件交给管理员。管理员在已配置 manjiao SSH 别名的 Windows 电脑、项目目录中执行：

.\scripts\grant_manjiao_git_access.ps1 -PublicKeyFile C:\path\manjiao_git.pub

管理员也可通过腾讯云终端，在 ubuntu 用户下使用项目里的 deploy/grant_git_key.sh 公钥文件路径 授权。新增公钥只允许 Git 命令；它能发布代码，但不能打开普通交互式终端。

第三步：新设备设置 SSH 别名

编辑用户目录下的 .ssh/config（文件名没有扩展名），追加：

Host manjiao-git
  HostName 43.139.101.102
  User ubuntu
  IdentityFile ~/.ssh/manjiao_git
  IdentitiesOnly yes

首次连接时核对服务器主机指纹，随后用 Git 命令验证：

git ls-remote ssh://manjiao-git/opt/git/aigc-short-drama-factory.git

能显示分支提交号即表示 Git 访问正常。ssh manjiao-git "echo OK" 被拒绝是正常现象，因为此公钥只允许 Git。设备丢失时由管理员删除该设备对应的 authorized_keys 公钥。

换网络时：检查腾讯云防火墙

轻量服务器控制台 → 实例 43.139.101.102 → 防火墙。需要从任意 IPv4 网络连接时，SSH 规则应为 TCP 22 / 来源 0.0.0.0/0 / 允许。这只允许发起网络连接，登录仍需要已授权的私钥。不需要开放全部端口或启用密码登录。

2026-09-09 已在腾讯云控制台核实：实例 lhins-2fz9aroh（43.139.101.102）共有 3 条防火墙规则，TCP 22、80、443 均为「全部 IPv4 地址 / 允许」。云端没有绑定原电脑 IP，本次无需修改规则。服务器内部 UFW 也已放通 SSH；登录仍使用授权公钥。规则可能被管理员后续修改，以控制台实时状态为准。

07 / DEPLOY AFTER MERGE

PR 合并后，手动发布服务器

在已配置 SSH 的设备、漫角项目根目录运行：

git switch main
git pull --ff-only origin main
pnpm deploy:server --check
pnpm deploy:server

--check 仅检查当前提交与 GitHub main 是否一致、服务器 Git 是否可读；正式发布才运行依赖安装、测试、类型检查、构建和服务器推送。部署成功后还会核对 deployed 提交和线上健康状态。

已有管理员电脑使用 manjiao 别名时，PowerShell 可先设置：

$env:MANJIAO_GIT_REMOTE = "ssh://manjiao/opt/git/aigc-short-drama-factory.git"

线上地址：manjiao.cloud。GitHub push 不等于上线，服务器 main 表示已接收版本，deployed 表示通过部署健康检查的版本。

同时只从一台设备发布。当前部署沿用项目已有脚本：备份失败可能仅告警，源码回滚不能自动恢复数据库；数据库结构变更需要额外审查并确认备份可恢复。更完整说明位于项目 docs/operations/github-and-multi-device-deployment.md。

08 / TROUBLESHOOT

遇到问题，先看“操作记录”

现象处理方式
找不到 git / node / gh 命令安装对应程序，并重新打开终端和工作台。
Repository not found / Authentication failed运行 gh auth status，检查登录账号是否有私有仓库权限；必要时重新登录并运行 gh auth setup-git。
GitHub 连接重置或超时检查网络。若使用代理，使用这台电脑实际运行的代理地址；不要直接照搬旧电脑端口。
工作区有改动，无法拉取 / 切换先保存、审查并提交需要的文件；个人草稿另存仓库外，或逐项确认忽略规则。不要直接清空文件。
已有暂存内容 / 冲突在编辑器或 Git 客户端检查暂存区和冲突，处理后刷新工具。
non-fast-forward / divergent branches两边有不同提交，需在编辑器中审查合并或 rebase。工具会停止，不会强推覆盖历史。
文件被保护或超过 5 MB环境配置 / 密钥不要提交；大文件在 Git 客户端审查，按项目要求使用 Git LFS 或素材存储。
SSH 连接超时检查服务器 IP、腾讯云 TCP 22 来源规则、当前网络是否允许 SSH 出站。
Permission denied (publickey)网络已通；检查用户 ubuntu、私钥路径，以及服务器是否添加了该设备公钥。
Could not resolve hostname manjiao-git用户目录 .ssh/config 尚未配置或文件名错误。
工作台提示“请刷新本机工作台”工具重启后旧网页令牌失效，刷新网页即可。
端口 4318 已使用先访问已有工作台，或停止旧实例；也可通过 PORT 环境变量换端口，按启动日志地址打开。
服务器推送成功但部署未确认检查 /tmp/manjiao_git_deploy_提交前8位.log。main 已接收但部署失败时，重复推送相同提交不会重跑 hook。

按需使用本机代理启动

下方 7890 仅是示例，需替换成这台电脑的真实代理端口。PowerShell：

$env:HTTPS_PROXY = "http://127.0.0.1:7890"
node server.mjs

macOS / Linux：

HTTPS_PROXY=http://127.0.0.1:7890 node server.mjs

这些命令在工具目录执行，不是项目目录。代理用于 GitHub 网络；它不代替 GitHub 登录或 SSH 公钥授权。

09 / KEEP IT PORTABLE

更新工具与保存手册

  1. 到 GitHub Releases 下载最新 ZIP。
  2. 解压到新文件夹；旧工具如果正在运行，先停止它。
  3. 启动新工具，再打开原来的项目目录。项目文件不会因更换工具而移动。

也可以拉取项目 main 中的最新 tools/git-workbench。便携文件夹没有保存登录凭据、私钥或项目数据，所以复制它并不等于复制账户权限。

版本：V1.1，2026-09-09。Windows 已验证运行；macOS / Linux 提供启动方式，尚未实机验证。
